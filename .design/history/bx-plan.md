# 阶段四：显式 bx 编译实施计划（已批准，首版已实施）

日期：2026-09-22。基线：`feat/native-reactivity`，本机配置恢复提交 `5107123`。用户已批准本计划，并将 ibind 更名为 bx；按推荐方向实施，允许通过探针比较后决定内部方案。计划获批不表示功能已实现。当前能力仍以 architecture.md 和三个包 README 为准。

## 实施结果

首版已落地 A 路径：Vue 稳定 computed + 元素 style，Svelte 原生 style 指令。完成单位与多绑定、有限脚本 class 复用、条件/简单 keyed 列表、SSR/hydration、HMR 和独立消费。具体成功支持范围和明确诊断的边界见 [bx 编译说明](bx-compiler.md)。动态 spread、嵌套 builder 绑定及复杂作用域仍不支持，不能从下列原计划推定已覆盖。

## 目标与已有基础（立项基线）

让显式 `bx` 在 Vue/Svelte 中更新元素 CSS 变量，同时保持 `css(factory): string`、普通值重算和哈希类名切换的合同。

典型验收样例（候选，尚不可直接执行）：

```ts
css((s) => {
  s.color.raw(color); // 普通值：依赖变化后重算，内容变化时换 class
  s.width.px(bx(width)); // 绑定值：独立更新元素变量
  s.transform.raw(`translate(${bx(x)}px, ${bx(y)}px)`);
});
```

其中 `color`、`width`、`x`、`y` 表示相应框架作用域内的值；Vue 脚本仍使用正确的 `.value` 读取。只改 width/x/y 时，回调执行次数、class 和规则数不增加，真实计算样式随之变化。若同一值还参与普通声明或控制流，它仍是普通依赖，不承诺消除这部分重算。

已有基础：core 样式引擎、三包原生上下文与完整字符串 SSR、真实框架浏览器测试、独立 tarball 消费测试及体积检查。bx 目前仅有类型标记和未编译时报错；适配器尚无 compiler 导出。本机原生 LSP 已在重启后通过 TS/Vue/Svelte 的错误检出、修复清零与五项语义工具验证。

## 推荐技术方向与备选

推荐在官方编译器处理组件之前，按 AST 识别导入和作用域，将绑定拆成“样式中的稳定变量引用”和“所属元素的原生变量更新”。最终组件仍交给官方编译链处理。

| 方向                                | 价值与成本                                                                             | 本阶段建议                                       |
| ----------------------------------- | -------------------------------------------------------------------------------------- | ------------------------------------------------ |
| A：组件源码转换，再交给官方编译器   | 容易查看生成源码；可复用框架的响应式与 SSR；需要处理源码映射、词法作用域和元素对应关系 | 优先做双框架探针，推荐方向                       |
| B：深入模板编译钩子或变换编译后代码 | 更接近框架内部执行点，但两端差异和升级耦合更大；SSR/HMR 必须分别处理                   | A 无法满足语义时，拿具体失败夹具比较后决定       |
| C：要求用户显式传递额外绑定描述对象 | 元素所有权明确，但改变现有作者体验，并增加 class 与绑定数据同步负担                    | 不作为首版默认；仅在无法可靠追踪的场景中另行评估 |

Svelte 优先验证原生 `style:--变量` 更新；Vue 比较原生 `:style` 合并与元素级指令/原生监听两种实现。先证明 SSR 初值、局部更新和清理正确，再确定 helper 和插件接口。不能直接把 Vue 的组件根节点 CSS 变量机制当作任意元素绑定的完整实现。

Vue 模板可能因其他状态更新而再次执行，因此只把变量读取挪到 style 并不足以保证回调不重跑。4A 必须验证稳定的计算边界：只跟踪普通依赖，同时保留组件和模板局部作用域。Svelte 同样测量实际回调次数，不凭生成代码外观判断。

## 首版范围

| 场景                                                          | 计划范围与处理方式                                                                     |
| ------------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| 原生 HTML 元素上的内联 css 回调                               | 4A/4B 首批闭环，先限定 Vue script setup 和 Svelte 5 runes 组件                         |
| 正确导入 bx、导入别名、局部同名遮蔽                           | 必须按符号和作用域识别；同时追踪 css 来自已知 useStyleRuntime 的绑定，不能按函数名猜测 |
| 标量值、单位方法、单个声明中的多个绑定                        | 首版必须支持；保留现有 token/raw 与参数类型约束                                        |
| 同一变量在 px/rem 等不同单位使用                              | 单独格式化，不错误共享值槽；覆盖多参数单位方法和普通值混合                             |
| 模板字符串中的独立 CSS 值及明确单位后缀                       | 支持可证明语义的子集；x/y 分别绑定，不能整段 transform 作为一个绑定                    |
| 同组件脚本中的 class 定义，被多个原生元素使用                 | 4D 支持有限、可静态追踪的 const/computed/$derived 形式；逐个使用点安装绑定             |
| 元素所在的条件分支、keyed 列表及模板局部变量                  | 4D 单独验收作用域、重排、替换和清理；通过前明确诊断                                    |
| 回调内部定义的变量、复杂控制流或任意函数调用作为绑定来源      | 首版保守限制，给源码位置和可执行的改写建议；不把 getter 越过词法或执行边界提升         |
| 组件透传、跨文件导出的 class、动态别名和无法追踪的 class 拼接 | 首版不承诺支持绑定；对已识别的含 bx 定义给明确诊断；普通 class 行为保持现状            |
| 动态 keyframes/global、Teleport、SVG/MathML、异步边界         | 不纳入首版成功支持矩阵，单独记录后续条件；不自动提升绑定到 :root                       |

支持矩阵描述的是编译绑定范围，不收窄已有普通 CSS API。暂不支持的 bx 写法不得静默丢绑定、回退成普通值或放宽类型掩盖问题。完全不可见的动态调用不宣称能被编译期穷尽发现，保留未编译 bx 的运行时报错。

## 分步交付

### 4A：两个官方编译链的最小探针

- 探针放 `.research/bx`，各用一个真实组件连接现有 dist；不创建产品导出或全套空插件。
- 覆盖导入别名、同名遮蔽、一个绑定值和一个普通值；验证错误能定位到原源码。
- 比较上述更新路径及计算边界，检查更新绑定值和无关状态时的回调次数。
- 尽早验证客户端、完整字符串 SSR 初值和 hydration，避免选出仅客户端成立的方案。
- 输出支持矩阵、转换前后代码、实际测试结果、所需依赖和剩余限制。未证明的能力继续标为候选。

退出条件：两框架均能实现“绑定值更新不重算、普通值更新仍重算”，且 SSR 首屏已有变量、hydration 无重复规则或样式跳变。若需要改变作者 API、依赖私有框架接口或扩大 core 协议，先把具体差异提交审阅。

### 4B：实现有限编译器和单位语义

- 在适配器 `src/compiler` 落实已选路径，按实际可用功能增加独立 compiler exports；测试夹具放对应包 test 目录。
- 分析导入、css 定义、bx 调用、变量读取及元素使用点，保留源码映射和定位诊断。
- 生成稳定变量 ID：统一项目相对路径和路径分隔符，区分调用位置、绑定位置和格式化上下文；不采用本机绝对路径或进程递增计数。
- 优先验证转换成现有变量引用/声明 API；仅在真实能力缺口出现时增加最小内部协议，不预设大范围 core 重构。
- 明确数值、负数、零值、字符串与非法值的序列化；不同单位分别输出，保持原有声明顺序及 fallback。
- 引号内插值、标识符片段和任意字符串拼接不能简单正则替换；`${bx(x)}px` 必须生成完整合法的 CSS 值，不能形成 `var(--x)px`。

退出条件：单位、多绑定、类型负例、宏识别及源码映射夹具通过；只改绑定值时规则稳定。变量名在同一次构建的客户端/SSR、不同机器 checkout 根目录之间一致；不承诺不同源码版本之间 class 永久不变。

### 4C：SSR、style 合并与生命周期闭环

- 服务端输出初始元素变量，沿用每请求独立上下文；不增加服务端全局可变缓存。
- 验证 hydration 后沿用 class 和样式规则，首次更新不出现变量缺失或跳变。
- 覆盖用户 style 字符串/对象/数组或框架支持形式、Svelte style 指令及动态 spread；明确合并顺序与生成变量命名冲突策略。
- 更新或解绑只处理本绑定拥有的变量；保留用户其他 inline style。原有 class 规则继续由 runtime/context 管理。
- 覆盖兄弟和嵌套实例、父子元素继承、卸载/重挂与绑定值校验失败后的状态一致性。

退出条件：两个请求、两个实例和嵌套实例互不串值；同一 class 可服务不同绑定值；卸载不影响其他元素；浏览器计算样式和 SSR 恢复均通过。

### 4D：脚本 class 复用与模板局部作用域

- 建立有限定义/使用点映射，验证同一 class 被两个原生元素引用时均取得正确变量。
- 保留一次计算 const 和响应式 computed/$derived 的既有区别，不把 const 自动改成响应式计算。
- 逐项接入条件挂载、keyed 列表、列表局部变量和重排；每项有独立正例与不支持形式的负例。
- 对无法保证所有使用点的定义及外逃路径给出诊断，不默默遗漏变量赋值。

退出条件：两端复用和列表状态隔离通过；作用域内初始化、更新及清理语义明确。超出支持矩阵的情况仍明确拒绝，不以扩大猜测性分析补齐。

### 4E：官方消费链、HMR 与交付

- 独立 tarball 消费 compiler 子路径，通过官方 Vite 插件构建客户端与 SSR；避免源码 alias 或仓库祖先依赖掩盖打包问题。
- 增加开发服务器 HMR 场景：修改、增加、删除绑定以及改变单位；验证旧订阅和元素变量清理。普通 class 旧规则仍遵循 runtime.dispose 的既有合同。
- 验证未配置编译器时有清楚报错；默认浏览器入口不包含 Node、AST、Vite 或编译器依赖。
- 完成三包 README、architecture、roadmap、handoff 的当前状态更新；只在相应验收通过后把候选 API 改为已实现。

退出条件：本地关键验证通过，CI 按对应提交报告实际结果，提交可换机继续；继续 private，不发布。

## 测试与交付规则

| 改动类型                     | 必做验证                                                             |
| ---------------------------- | -------------------------------------------------------------------- |
| 每个产品实现阶段             | 根 `pnpm check`、`pnpm build`；原生 LSP 检查修改文件；针对性单元测试 |
| Builder、单位转换或生成类型  | `pnpm test`、`pnpm test:types`；保持独立规范负例                     |
| CSS 生成器或数据             | `pnpm generate:css`、`pnpm generate:check`，不手改生成文件           |
| 响应式、上下文、元素生命周期 | `pnpm test:unit`、`pnpm test:browser:frameworks`                     |
| 序列化、资源注册或 SSR 恢复  | `pnpm test:browser:core` 及相应框架 SSR/hydration 场景               |
| compiler 导出、依赖及打包    | `pnpm test:consumer`、`pnpm size:check`                              |
| 语言服务桥或相关依赖         | `pnpm lsp:verify`；仅新增编译器不默认改语言服务桥                    |

现有命令缺少覆盖时，在对应阶段补测试入口并接入根快速测试或相关 CI job，尤其注意当前快速测试入口尚未枚举 Svelte 编译器单元测试。每个 CI job 构建一次，后续使用 `--no-build`。耗时全量回归可交给 CI，本地完成类型、构建及本次改动的关键路径；本地通过、CI 通过和 CI 未完成分别报告。

每个聚焦阶段验证通过后用中文提交。清理本轮探针与临时消费者，失败时保留必要证据；不关闭其他项目 Node 进程。报告保留绑定更新前后的回调次数、class、规则数、元素变量和计算样式，不能只用编译快照替代运行时验收。

## 已批准的实施决策

1. 采用 A 作为优先方向，先完成 4A 双框架探针，再根据实测收敛 Vue 更新方式和编译接口。
2. 首批聚焦原生 HTML 元素；同组件脚本 class 复用、条件和列表属于 4D，组件透传/跨文件绑定/动态资源另行规划。
3. 按 4A–4E 推进，以完整字符串 SSR、类型体验、HMR 和独立消费作为阶段四完成标准。

以上范围已经批准，按范围连续实施；常规内部选择以测试结果决定，只有实质改变已批准 API、范围或技术边界时再次提交具体方案。

## 官方依据与尚待实测部分

- [Vue SFC CSS v-bind](https://vuejs.org/api/sfc-css-features#v-bind-in-css)：官方机制将变量写入组件根节点，可作为先例，但不能证明本项目的任意元素绑定方案成立。
- [Svelte compiler](https://svelte.dev/docs/svelte/svelte-compiler)：提供解析、预处理和源码映射能力。具体接入顺序以项目锁定版本及 Vite 消费探针为准。
- [Svelte style 指令](https://svelte.dev/docs/svelte/style)：支持元素 CSS 自定义属性和与 style 属性组合；冲突与优先级必须纳入本项目验收。
- [Svelte derived](https://svelte.dev/docs/svelte/$derived)：派生依赖来自求值中的响应式读取。本项目 css 包含幂等注册副作用，不能笼统称为纯计算；稳定计算边界仍需实际组件证明。

官方资料只证明相关扩展能力。本文推荐的 bx 转换、Vue 缓存策略、复用分析与完整 SSR/HMR 行为的首版范围已由产品夹具实测，扩展范围以 bx-compiler.md 为准。
