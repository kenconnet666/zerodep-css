本轮按[五阶段规划](next-stage-stability-and-themes.md)实施。保留运行时 CSS、类继承、下划线选择器、单一 css 组合入口；五包仍为 private。

## 已完成的工作

1. 复现并修正循环、catch、switch 及函数 var 提升对 css 导入的遮蔽，修正 Vue.computed 命名空间写法的回退。纠正文档中已过期的“功能尚未提供”描述。
2. 建立真实 Vite 开发服务的 Vue/Svelte HMR 与生命周期 CI，覆盖模板、脚本、动态声明删除、选择器变化、列表换 key 和 30 次挂卸。测试目录避开 Vite 忽略的 test-results；连续模拟编辑跨过 watcher 的事件节流窗口。
3. 编译提示和开发运行时覆写提示携带作者文件 / 行列；逐语句处理源码映射，未改写语句不再全部映射到 script 开头。生产输出没有定位字典。cssStats 细分普通类、动画、全局块、私有值规则。
4. 可选 core/theme 提供 ThemeCss、六类主题属性和亮暗两套声明；15 个语义色。Vue/Svelte 样板验证两层继承、父级切换、子树覆盖、兄弟隔离与撤销覆盖，真实 Nuxt/Kit 验收覆盖 SSR、hydration、静态页面与 CSP。
5. 将稳定浏览器验收移到 test/browser，保持现有测试命令可用。CI 分别测量 200 / 1,000 项和无关更新；依据结果加入小范围的平铺模板缓存，继续对可变数组按原语义求值。

## 生命周期边界

两个框架起始均为 21 条私有值规则。20 项列表换新 key 十次后为 221 条；卸载后均为 0，卸载后继续修改共享响应式值也没有重建私有绑定。模板 / 脚本热更新没有整页刷新，兄弟组件正确。

含 HMR 和 30 次挂卸的整个用例结束后，普通类仍保留：Vue 915 条，Svelte 936 条。它们是宿主缓存，不应误报为“所有规则都已回收”；本轮没有用 LRU 或 DOM 扫描强行删除外部仍可能持有的类。无限增长的 key 在同一组件里仍保留 frame 记录直到组件退出。推荐用独立行组件明确生命周期，见[使用边界](../docs/lifecycle-and-diagnostics.md)。

## 性能结果

GitHub Ubuntu runner，Node 24.21.0，Chromium 153.0.8010.12，固定 Vue 3.5.43 / Svelte 5.57.0 / Emotion CSS 11.13.5。每项三轮、轮换顺序，时间包含框架刷新与布局读取。200 / 1,000 项分别执行 20 次连续新值更新和 10 次无关更新，不与其他重负载测试并行。

1,000 项的中位数：

| 框架 / 路径               | 挂载 ms | 20 次更新 ms | 10 次无关更新 ms | 最终规则数 |
| ------------------------- | ------: | -----------: | ---------------: | ---------: |
| Vue 隐式绑定              |    42.2 |        208.1 |             31.5 |      2,000 |
| Vue 关闭模板缓存的对照    |    42.3 |        223.6 |             41.6 |      2,000 |
| Vue 普通运行时            |    26.6 |        304.5 |             18.9 |     21,000 |
| Vue 手工变量              |    22.2 |        127.3 |             23.5 |          1 |
| Vue Emotion               |    35.9 |        331.5 |             21.2 |     21,000 |
| Svelte 隐式绑定           |    53.4 |        222.9 |              1.3 |      2,000 |
| Svelte 关闭模板缓存的对照 |    51.5 |        232.3 |              1.3 |      2,000 |
| Svelte 普通运行时         |    32.1 |        318.3 |              1.5 |     21,000 |
| Svelte 手工变量           |    23.7 |        133.4 |              1.5 |          1 |
| Svelte Emotion            |    37.0 |        370.8 |              1.4 |     21,000 |

模板缓存对照在同一 runner 使用同一份源码，仅研究副本关闭缓存；不是拿不同机器的结果直接相减。1,000 项中，缓存使 Vue 无关更新中位数减少约 24%，连续更新减少约 7%；Svelte 连续更新减少约 4%。200 项 Vue 连续更新则从 42.3 ms 变为 44.2 ms，挂载也有额外初始分配，因此不宣称全场景更快。保留此小优化的理由是大列表中重复登记确实减少，并有原生数组语义与输出回归约束。

两种隐式路径在所有无关更新样本中 CSSStyleDeclaration.cssText 写入均为 0。Vue 仍有组件重渲染的 JS 成本，Svelte 的细粒度更新在该用例中跳过了列表。这个计数没有覆盖所有可能的 DOM API，不能等同于任何框架完全没有执行工作。

隐式绑定保持规则数稳定，但首次挂载比普通运行时更贵，速度仍落后于手工 CSS 变量。这些是本用例结果，不等于原生 CSS，也不外推为应用整体收益。

## 本轮未扩张的范围

公开发布、流式 SSR、边缘平台、Shadow DOM、跨独立应用的样式合并，以及 portal 自动保留主题继承，仍不在当前验收范围。用户覆写和无法可靠转换的表达式保持运行时回退。没有增加 recipes / variants、公开 var 方法、Worker / SIMD 或 CSS 解析层。
