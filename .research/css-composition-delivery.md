# 统一 css 组合入口

原独立 `cx` 函数及 `ClassNames` 类型已删除，不保留兼容别名。`css` 的输入为 `CssInput`：声明字符串、当前宿主已登记的样式类、递归只读数组、`false` / `null` / `undefined`。输出始终是一个生成的样式类名。

```ts
const base = css(s.padding.px(8), s.color.red);
const button = css(base, active && s.color.blue, [s.borderRadius.rem(0.5)]);
```

标记、外部 class 与条件对象交给框架模板组合，`ic`、`keyframes`、`globalCss` 的片段参数继续为字符串。完整用法与限制见 [作者 API](../docs/author-api.md)。这项决定取代上一阶段单独提供 cx 的方案。

实现复用现有登记表和内容缓存，不解析 CSS、不删重复属性。普通声明不查询类名表；只有本库的 `z-` 前缀候选才精确查表，未登记的字符串仍原样拼接。只修改函数自己收到的 rest 数组，避免普通路径另建展开数组，用户传入的数组不会被修改。组合结果继续关联隐式变量目标，不改变 SSR 恢复流程。

绑定转换同时覆盖数组和逻辑条件右侧的动态声明；条件仍按原 JS 时机选择结构。补了“条件曾经启用、后来没有读者”的卸载清理，避免值规则遗留。Vue/Svelte 绑定样板从每组 33 条降为 32 条，省去原先仅供合并的中间背景类。

本地焦点验收包含五包构建 / 类型入口、核心运行时与绑定协议、作者 API 浏览器用例、Vue/Svelte 客户端及 SSR 恢复。完整元框架、跨平台、LSP、浏览器与性能正确性回归交给当前提交的远程 CI。

为避免凭入口简化推断性能，本轮用 Node 24 将登记器与 `5f56f88` 比较：16 个已缓存组合，每轮 20 万次两段声明调用，预热后五轮交替次序取中位数。最初的额外展开数组方案约 77.7 ms；复用 rest 数组、快速排除非类名字符串后，最终对照为旧版 61.8 ms、新版 64.6 ms，约增加 4.5%。这是纯登记器命中微基准，不能当成页面差距；新能力有输入分类成本，而直接追加声明可省掉原先的中间类登记。本轮没有新增参数组合缓存或运行时 CSS 解析器。
