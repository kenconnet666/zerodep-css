# 编译期预计算研究

2026-09-23，生产基线 c98995c。本轮仅新增 `.research` 探针与研究文档，没有修改 core、适配器或编译插件。推荐继续研究「规范化 CSS 内容 + 不含最终类名的规则模板」，运行时按实际使用注册。以下性能是隔离原型结果，不是已发布功能的收益。

## 为什么当前准备缓存还不够

当前 prepareStyle 提供稳定的站点身份；runtime 第一次遇到该站点时仍需执行 Builder、序列化、语法解析、类名计算和注册。缓存命中后已经不再做这些计算。因此预计算针对首次使用、缓存驱逐后重建、新 SSR 请求；不能把这一收益解释为持续更新普遍加速。

类名哈希包含 OutputConfig：namespace、layers、layer、format。不能在构建时用默认配置产生最终类名，然后用于任意 runtime。nonce、Document/ShadowRoot、规则预算和注册所有权也不属于编译产物。

## 实验方案与范围

| 方案     | 构建期产物                      | 首次运行时仍做什么                          |
| -------- | ------------------------------- | ------------------------------------------- |
| baseline | 当前准备函数及原回调            | Builder、序列化、全部解析、类名、注册       |
| ir       | 有序样式结构和元数据            | 序列化、全部解析、类名、注册                |
| body     | 规范化 CSS 内容、声明数、元数据 | 类名、完整记录校验、注册解析与注册          |
| template | body + 规范化规则尾部           | 按实际配置算类名并组装外层规则、注册        |
| full     | 固定配置的完整记录及解析结果    | 配置/诊断条件匹配后注册；不匹配时回退原路径 |

所有方案保留原回调作为回退。没有提前向 DOM、SSR manifest 或全局 runtime 注入规则。原型通过 esbuild onLoad 改写临时 bundle，生产文件未改动。节点计数另用插桩 bundle；正式计时没有解析计数器。

预计算器先调用现有 automaticDeclarations，再使用更窄的 AST 解释器生成 Builder 操作。它只读取字面量、已知属性/结构方法和可确定的 if 分支，不 eval 源码、不导入执行用户组件、不调用任意用户函数。示例的原生 JS 回调作为独立对照。原型尚不支持 switch 等全部既有静态分析能力，不能直接当作新编译器接入。

特别检查了未选分支中的声明：即使分支永远不执行，函数/var 的提升仍可能影响实际作用域。原型遇到函数声明、变量声明或类声明直接回退；正式实现需要共享词法作用域证明，不能仅凭「选中分支没有外部读取」就执行或删除其他代码。

## 测量结果

Node 24.12.0、Chrome 153.0.8010.52；每项预热后 7 轮交替顺序取中位数。没有与旧机器或前一轮数据拼接计算。64 个不同的静态站点，包含普通声明、hover、media 和样式命名。

### Node

| 场景                                |  baseline |        ir |      body | template |     full |
| ----------------------------------- | --------: | --------: | --------: | -------: | -------: |
| 一个新 runtime 首次使用 64 个站点   |  26.19 ms |  23.08 ms |  13.86 ms |  1.37 ms |  0.82 ms |
| 25 个独立请求，每请求使用 64 个站点 | 435.30 ms | 376.48 ms | 210.68 ms | 20.99 ms | 17.09 ms |
| 缓存预热后调用 20,000 次            |  22.47 ms |  24.02 ms |  20.59 ms | 22.24 ms | 23.75 ms |

请求场景包括 runtime 创建、css 调用、renderStyles 和 dispose，不包含 Vue/Svelte 整页 SSR 渲染。热调用计时排除首次填充缓存；仍包含结果输出和清理的少量公共成本。

旧路径对旧路径控制组：首次使用为 24.97～26.59 ms，请求场景为 429.38～467.59 ms，热调用为 18.37～22.04 ms。ir 的小幅收益需谨慎解读；template 的首次计算差异明显超过此控制组波动，热路径不宣称收益。

一个示例首次使用的库内解析次数：baseline/ir 都是 5 次 value、5 次 declaration、1 次 selectorList、3 次 stylesheet，总计 14 次；body 剩 2 次 stylesheet；template/full 为 0 次。浏览器自身的 CSS 解析、CSSOM 插入、样式计算与布局没有消失。

### 真实组件

每个组件 192 个元素引用 64 个静态站点，使用官方 Vue/Svelte 编译器。研究后端手工接入生成代码，不代表正式 cssPlugin 已支持预计算。模块加载后预热组件，再测新 context 的挂载；数据不包含网络传输、首次 JS 解析或首次模块执行。

| 场景                    | baseline |      ir |    body | template |   full |
| ----------------------- | -------: | ------: | ------: | -------: | -----: |
| Vue 首次挂载            |  26.1 ms | 23.3 ms | 17.7 ms |   6.1 ms | 5.0 ms |
| Vue 隐藏分支首次显示    |  19.3 ms | 20.1 ms | 13.6 ms |   4.3 ms | 5.2 ms |
| Svelte 首次挂载         |  21.3 ms | 19.2 ms | 12.8 ms |   6.3 ms | 6.4 ms |
| Svelte 隐藏分支首次显示 |  18.7 ms | 18.0 ms | 12.9 ms |   5.5 ms | 4.9 ms |

旧路径对旧路径挂载控制组：Vue 16.3～19.1 ms，Svelte 19.1～20.4 ms。不同运行的绝对时间不能交叉相除。原型明显减少该场景的首次计算，但不宣称整个页面或真实业务应用有同等比例提升。Svelte 无关状态更新本就不重算静态 class；Vue 热更新也没有稳定收益证明。

| full                             |      47,275 |     5,451 |

这是相似结构的样本，gzip 重复压缩效果较好，不能外推所有应用。template 比 baseline 多 17,782 个未压缩字节和 901 个 gzip 字节。实际整份组件 bundle（包含框架、core、回退与原型桥）中，template 的 gzip 增量为 Vue 1,538 字节、Svelte 1,608 字节。保留运行时能力后 css-tree/Builder 仍在包内；没有获得「零运行时」包体积。

构建 64 个站点的 AST 分析、Builder 和 body 预计算，5 次为 26.51～47.49 ms，中位约 30.81 ms；不是完整应用/Vite 构建成本。尚未测完整规则模板生成的构建耗时、浏览器冷加载/堆内存、大量异质站点和多 chunk 去重。不能据此决定默认对所有站点启用。

## 为什么推荐规则模板，而非固定配置完整规则

当前局部静态样式的外层形式已知：普通类规则，以及可选的 layer 包装。构建时用已校验的内容生成 `.preheat{...}`，验证恰好一条局部规则、无资源注册，再保存去除固定类名前缀后的规范化尾部。

运行时依据真实配置计算 id，再拼接 `.` + id + ruleTail；需要 layer 时再包装。不是在整段 CSS 内对某个占位符做字符串替换，因此声明中的字符串不会被误改。原始规范化 body 单独保留，继续用于原来的内容哈希和 manifest，避免改变类名。

template 已对不同 namespace、layer 和 debug 配置验证等价。full 依赖固定配置和诊断条件，匹配失败会退回原回调，而且体积更大；目前没有足够理由优先选择它。

## 正确性证据与尚未完成的合同

已通过的研究检查：

- 不同 namespace、layers、runtime debug 下与当前实现的完整记录等价；命名、来源、局部 debug 覆盖保留。
- 空值、显式 var 字符串、声明顺序、important、嵌套结构和字面量 if；动态值、未知调用、async、非法数值和不安全声明回退。
- 检出构建期 CSS 序列化失败，并核对原运行时仍在调用时才报错；完整编译链中「捕获预计算失败并输出原回调」的接线尚未实现。隐藏分支不提前注册已经由真实组件验证。
- 派生 Css 不消费系统基类预计算结果；版本不符回退；256 项缓存驱逐后重建没有重复注册。
- runtime dispose 和 maxRecords 仍生效；SSR manifest 恢复仍走现有校验。
- 真实 Vue/Svelte 的 baseline/template 完整字符串 SSR、两个请求隔离、隐藏 SSR、浏览器 hydration、恢复后更新与清理。
- 浏览器逐个检查 192 个元素的宽度、记录顺序/内容等价，外部禁用样式表后仍拒绝命中，卸载/释放 context 后没有样式残留。

这些不等于产品验收。template/full 为受信任的研究产物跳过解析，没有完成公开内部入口的解码器与完整错误合同。生产接入必须完成：

1. 产物版本、规范化算法/数据版本、格式与内容身份契约；版本不匹配走回退。checksum 不能被当作安全认证。
2. 产物形状、不可变性和资源边界验证；编译产物与来自外部的 SSR manifest 使用不同入口，不能因为预计算而放宽 manifest 校验。
3. 将纯规范化实现复用到编译端与运行时，不维护两套 CSS 序列化规则；将已验证计划交给现有注册事务，不新增独立注册器或自有响应式缓存。原型的 WeakMap 只是接线工具，不是建议的生产缓存架构。
4. 保留宿主检查、冲突检查、注册失败回滚、预算与重入保护；补充破损产物、ShadowRoot、nonce/CSP、DOM 删除、插入失败、多组件来源合并和三浏览器差分回归。
5. 编译产物的安全 JS/SFC 序列化、source map、HMR 身份失效、客户端/服务端产物一致性，以及独立包消费。
6. 对任意新引入的提前报错、注册顺序变化或资源行为变化单独讨论，不能把它们隐藏在性能优化中。

原型保留了现有事务，但没有逐项重新验收上述全部边界。没有修改生产代码，也没有把全量 CI 成功当成原型正确性的证明。

## 推荐落地顺序

第一步只支持系统 Css 的完全静态局部样式，复用当前安全分析，产出规范化内容和配置无关的规则模板。原作者 API、调用位置、按需注册和 fallback 不变。产物是模块级不可变定义，runtime 结果继续使用既有 256 项缓存，框架响应式仍由 computed/$derived 管理。

第二步评估现有动态单位转换后形成的固定 `var(--...)` 结构：只预计算固定结构，变量读取与更新仍交给框架。本轮没有测量这条完整自动编译链，不把它当作已证明收益。

暂缓动画、全局规则、资源依赖和派生类。动画引用的 id 同样依赖 runtime 配置，不能把它们直接当作配置无关字符串；全局 key、更新/释放、@property 冲突和 SSR 认领也需要额外设计。

不建议在应用启动或 SSR 请求创建时提前运行全部 css 回调来「暖缓存」：这样会提前执行分支、产生未使用规则并改变注册时机。编译期预计算只搬运纯计算，不搬运应用副作用。

## 外部参考

[StyleX 官方文档](https://stylexjs.com/docs/learn/styling-ui/defining-styles/)采用静态可分析约束，动态样式生成固定 CSS 及运行时变量值；可参考其「固定结构与动态值分开」思路，但本项目不把其使用限制施加给全部运行时代码。

[vanilla-extract](https://github.com/vanilla-extract-css/vanilla-extract)在构建期提取样式，[dynamic API](https://vanilla-extract.style/documentation/dynamic-api/)负责变量更新。其静态样式资产模型提供参考；本项目仍需保持实际使用点注册、runtime 配置及请求所有权，不能直接照搬为全局 CSS 文件。
