# 当前性能与取舍

运行时 CSS 已恢复为正式能力；**仍有相对原生 CSS 和成熟运行时库的开销，不能称为已经追平**。以下是 2026-09-24 的本机结果，产品基线为 f63ac11，优化版本加入简单变量结构快路径和主题长键复用。旧架构结果保存在 [Git 历史](https://github.com/kenconnet666/zerodep-css/blob/f63ac11/docs/performance.md)，不要与本轮拼接计算提速。

## 方法与范围

Vue 3.5.43 与 Svelte 5.57.0 分别通过官方编译器运行真实组件，Chrome 153.0.8010.53、Node 24.18.0。每项 200 个元素，轮换执行顺序，取 5 轮中位数。普通场景预热 5 次、计时更新 30 批；全新值场景预热 1 次、计时更新 5 批，每一行每一帧均使用不同值。表中的更新耗时是整组总耗时，包含框架调度与每批布局读取。

挂载单独记录，JS/CSS 资产加载、网络与首次 JS 解析不计时。Native/vanilla-extract/UnoCSS 使用预生成规则；Emotion/goober 各用独立实例或目标节点。主题对照使用相同叶数量和值；原生 CSS 从共同数据独立生成，不调用本库引擎。每次都检查 class、计算宽度、主题值、规则数量与清理。

自动编译样本使用同 SFC 的直接 createStyles/useCss，属于可分析路径。跨模块项目 hooks 仍为运行时；ThemeCss 构造器配置行也明确记录为运行时回退。静态 Svelte 表达式能避开无关状态更新，不能假设两框架调用了相同次数的 CSS 回调。小于 1 ms 的结果只视为很小，不排名。

## 16 个循环值：30 批更新

| 路径                       | Vue 总耗时 | Svelte 总耗时 | 动态生成记录 |
| -------------------------- | ---------: | ------------: | -----------: |
| 原生预定义 class 切换      |    33.1 ms |       33.5 ms |            0 |
| vanilla-extract class 切换 |    32.8 ms |       33.2 ms |            0 |
| UnoCSS class 切换          |    33.0 ms |       32.3 ms |            0 |
| Emotion 对象 css 调用      |    44.2 ms |       44.5 ms |           16 |
| goober 对象 css 调用       |    39.1 ms |       43.8 ms |           16 |
| 本库运行时 class           |    69.0 ms |       83.1 ms |           16 |
| 原生 CSS 变量更新          |    71.2 ms |       70.4 ms |            0 |
| Emotion 固定变量规则       |    72.7 ms |       70.4 ms |            1 |
| 本库自动变量绑定           |   134.6 ms |      158.7 ms |            1 |

这个工作负载里，本库运行时约为原生 class 路径的 2.1 倍 / 2.5 倍，约为 Emotion 对象路径的 1.6 倍 / 1.9 倍。自动变量并非每次更快：它减少规则增长，但还有 Builder、参数格式化、缓存查询和框架属性更新成本，浏览器更新变量的成本也与切 class 不同。

静态样式可在 setup 中计算一次并复用字符串；这一路径的 Vue 更新约 2.3 ms，原生约 2.6 ms，不能把小差异当成领先。每次 Vue 渲染调用运行时静态回调约 33.9 ms，静态准备约 6.6 ms。Svelte 的同类无依赖更新均小于 1 ms，主要差别在初次挂载，不能据此说其运行时计算免费。

## 每帧全新值：5 批更新

| 路径                 | Vue 总耗时 | Svelte 总耗时 | 挂载＋预热＋更新后的记录 |
| -------------------- | ---------: | ------------: | -----------------------: |
| 原生变量             |    12.4 ms |       11.9 ms |                        0 |
| vanilla-extract 变量 |    12.9 ms |       11.8 ms |                        0 |
| UnoCSS 变量          |    13.0 ms |       12.4 ms |                        0 |
| Emotion 新规则       |    20.9 ms |       22.3 ms |                     1400 |
| goober 新规则        |   668.1 ms |      658.3 ms |                     1400 |
| 本库自动变量         |    21.8 ms |       28.1 ms |                        1 |
| 本库运行时新规则     |   158.4 ms |      187.1 ms |                     1400 |

这里自动变量的主要价值很明确：同样持续变化时保持一条内容规则。未经优化的运行时每批平均约 31.7 / 37.4 ms，包含 200 个元素的全新规则与布局，属于不适合频繁执行的负载。不能将这些 5 批数字与上一表 30 批直接相除，也不能把一次桌面测试推导为移动端帧率。

对于小而有限的状态集合，运行时 class 缓存有实际价值；连续数值优先使用可分析的自动绑定，或普通 CSS 变量/原生动画。插件的 bindings:'runtime' 保留全运行时模式，适合禁用元素变量的 CSP 等场景；它不是普遍的速度开关。

## 主题与本轮优化

相同主题树下，Vue/Svelte 的原生主题 class 更新为 36.9 / 38.3 ms；本库 ThemeCss 运行时路径为 180.6 / 225.0 ms。主题变量与宽度一起更新时，原生变量路径为 148.1 / 134.6 ms，本库自动路径为 205.8 / 281.7 ms。主题场景仍有差距，尚不宣称主题性能优化完成。

CPU 采样定位到重复值结构扫描与缓存处理。此次仅做两项无状态、小范围优化：

- 精确的 ASCII var(--name) 已能证明结构完整，直接跳过 tokenizer；fallback、注释、转义、空白和其他形态继续完整检查。
- 内部主题准备键已经包含全部冻结内容，无来源时直接复用原字符串，避免每个元素重新拼接长键。缓存命中仍检查宿主；可观察元数据读取、来源区分与工厂执行次数保持原合同。

两次隔离源码成对 Node 测量中，相关变量场景下降约 18%—25%，主题场景下降约 29%—32%。每项 30,000 次、预热 3,000 次、7 轮交替，完整 snapshot 与工厂调用次数一致才计时。旧对旧控制约有 -13% 到 +10% 的波动；其他小差异不作结论。两次浏览器运行之间也有明显波动，因此上表报告当前结果，不把所有变化都归因于这两项优化。

## 体积与使用判断

P3b 完整 css 入口约 517 KB minified / 107 KB gzip；Css 作者入口约 2.2 KB / 0.8 KB，cssVar 约 0.4 KB / 0.3 KB。小入口不代表完整运行时大小。横向准备资产中的 Emotion create-instance 约 15.6 KB / 6.4 KB gzip，goober 约 2.3 KB / 1.3 KB；它们的功能边界与本库完整 DSL、资源和 SSR 校验不同，但本库的额外下载与解析成本确实存在。

本库当前的收益是带类型的作者模型、普通 JS 控制流、组合、主题和框架生命周期接入，不能用这些特性掩盖性能差距。后续优化继续依据热点与等价性证据选择，始终保留运行时能力；不会为追求某个数字改写 getter 求值、空值、省略、覆盖或 SSR 语义。
