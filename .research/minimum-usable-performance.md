# 最小可用阶段性能记录

这轮测量使用已构建的 `core`、Vue、Svelte 包入口，不沿用最初单宿主探针的速度结论。Windows、Node 24.18.0、Chrome 153.0.8010.54；Vue 3.5.43、Svelte 5.57.0、Emotion CSS 11.13.5。Vue 与 Svelte 分开测，每种场景有 200 个元素、三轮交错顺序；整套测试独立执行两次。表中是每次运行三轮中位数构成的范围，单位毫秒，越低越好。每个用例使用新浏览器页面，并验证全部元素的计算样式与规则数量。原始数据见 [dist 第一轮](string-css-probe/results/results-mup-dist-a.json)、[dist 第二轮](string-css-probe/results/results-mup-dist-b.json) 和[冷加载数据](string-css-probe/results/results-mup-dist-cold.json)。

| 场景与写法                           | Vue 更新耗时 | Svelte 更新耗时 | 更新结束后新增规则 |
| ------------------------------------ | -----------: | --------------: | -----------------: |
| 16 种值，预声明的原生类              |    42.6–42.9 |       42.1–59.9 |                  0 |
| 16 种值，本框架直接 `css(...)`       |    42.4–45.1 |       48.5–52.6 |                 16 |
| 16 种值，本框架预注册 16 个类后查表  |    41.4–42.6 |       42.9–45.4 |                 16 |
| 16 种值，Emotion 接收相同字符串片段  |    50.8–66.9 |       54.7–59.1 |                 16 |
| 16 种值，手写 CSS 变量绑定           |    85.1–93.4 |       92.3–98.8 |                  1 |
| 持续新值，原生 CSS 变量绑定          |    17.8–24.8 |       19.1–20.5 |                  0 |
| 持续新值，本框架直接 `css(...)`      |    25.0–31.3 |       25.1–28.4 |              1,400 |
| 持续新值，Emotion 接收相同字符串片段 |    33.0–35.0 |       36.3–42.1 |              1,400 |
| 持续新值，本框架手写 CSS 变量绑定    |    17.7–21.3 |       18.9–19.9 |                  1 |

有限值场景是 30 次宽度更新；持续新值场景是 5 次更新。耗时包含框架刷新和一次布局读取，不是单独的 `css()` 调用时间。预声明类和原生变量是浏览器基线，分别省去了运行时注册或采用不同的变量语义，不能宣称它们与运行时逐值生成类完全等价。Vue 的无关更新会让模板中的直接 `css()` 再调用，放入 `computed` 可避免；Svelte 的直接模板在这项无关更新中已经不重复调用。有限值的样式可由缓存稳定复用；持续新值使逐值生成的规则按预期增长，后续如实现编译器变量绑定，需要单独权衡这两组场景，不能无条件声称变量更快。

冷加载探针把压缩后的 IIFE 注入全新页面，只测浏览器解析和执行，不含网络下载、完整应用挂载或 CSS 规则注册：

| 单独入口                   | 压缩后字节 | 首次执行中位数 |
| -------------------------- | ---------: | -------------: |
| 本框架浏览器规则注册器     |      2,140 |         1.3 ms |
| 本框架完整 `core` 作者模型 |    591,169 |        22.0 ms |
| 本框架 Vue 入口            |    596,978 |        23.1 ms |
| 本框架 Svelte 入口         |    634,159 |        59.4 ms |
| Emotion CSS 入口           |     15,734 |         2.8 ms |

这不是同功能包体积比较：完整作者模型带 502 条属性链和 12,586 个关键字，Emotion 入口没有这套作者数据。最初的全部急切初始化在同机探索中让 `core` 首次执行约 83 ms；改成属性首次读取时初始化、之后共享后，最终包约 22 ms。其余浏览器、并发 Node SSR 和 hydration 验收保持通过。Node 数据 URL 测试包的一次导入约 Vue 278 ms、Svelte 56 ms；暖机后渲染单个按钮约 0.10/0.04 ms。这些微型 SSR 数字不代表真实页面请求延迟。

目前可下的结论是：有限值缓存类的端到端更新时间已接近本测试的预声明原生类；持续新值的运行时类仍比原生变量路径慢并带来规则增长。相同字符串输入下本实现通常快于 Emotion，但跨轮波动存在，不能推断所有组件或浏览器都如此。性能热点主要是完整作者模型首次加载和新规则插入；规则注册器本身很薄。下一步的优化应由实际应用负载决定，暂不为了追逐微基准加入 CSS 解析器或强制编译器。

复测命令：先在仓库根运行 `pnpm build`，再在 `.research/string-css-probe` 运行 `pnpm install --frozen-lockfile`；以 `MUP_DIST=1` 分别执行 `pnpm probe:mup` 和 `pnpm probe:mup:cold`。在 Windows PowerShell 中可先执行 `$env:MUP_DIST='1'`。真实性能计时应串行运行；CI 只验证功能正确性，不把共享机器的计时作为性能回归门槛。
