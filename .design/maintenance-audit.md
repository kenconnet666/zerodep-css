# 0.2 基线后的维护审查

后续作者体验与性能改造见 [API 易用性](api-usability.md)，其中更新了当前组件提供主题后的隐式读取行为；下列记录保留本轮当时的验收。

本轮依据用户授权直接实施，保留混合运行时架构，不引入 recipes/variants 或新的主题状态管理层。

## 范围和阶段

1. 检查编译优化的副作用边界、局部配置校验、测试目录和清理生命周期；修复可复现问题后单独提交。
2. 增加 `readTheme(definition, scope?)` 和适配器 `useTheme(definition, scope?)`：前者返回当前冻结快照，后者返回捕获组件作用域的读取函数。无 provider 使用该定义默认值；同名不兼容 schema 报错；调用读取函数时追踪框架原生依赖，不增加订阅。
3. 补充类型、请求隔离、真实 Vue/Svelte 更新与 SSR 恢复测试，更新公共文档，检查独立消费和体积，交由 CI 完成全量回归。

## 审查边界

- 文件整理仅迁移仍在使用的测试临时目录，历史研究保留；不为缩短文件而拆分稳定的核心事务代码。
- 静态优化必须同时检查函数体和参数初始化。未证明安全的回调继续执行运行时路径。
- 新 API 只读取主题；不写全局状态、不注册样式、不读取 DOM、不接管 runtime 生命周期。
- 本地和 CI 证据分别记录，未运行的检查不记为通过。

## 结果

第一阶段已修复并通过本地 check/build、99 项快速测试和真实 Vue/Svelte Vite HMR：

- 默认参数中的副作用可能被静态缓存跳过；根与嵌套回调均检查完整签名，异步、生成器、额外参数、默认参数、rest 参数保留运行时路径。修复前新增 Vue/Svelte 负例均失败，修复后通过。
- config 原先接受非普通对象、symbol 和不可枚举未知字段；现严格拒绝且失败不注册样式，允许无原型的配置数据对象。修复前负例失败，修复后通过。
- HMR 独占临时目录从历史 `.research/bx` 移入 `scripts/testing/.hmr-*`；正常执行后清理，并在浏览器启动/关闭失败时仍执行路径核验和目录回收。旧研究数据不改动。
- 路线图基线修正为 0.2.0。

第二阶段已实现主题读取 API：

- core 的 readTheme 按 name/schema 查找当前作用域快照，不复制、解析或注册规则；无对应 provider 返回调用方定义的 defaults。
- Vue/Svelte 的 useTheme 初始化时捕获作用域，返回 getter；调用时追踪 computed/rune 原生依赖，无自建 store 和订阅。provider 自身传显式 scope，后代自动取得上下文。
- 重用既有 schema 检查，并把内部 inherited 更名为 findTheme，反映供解析和只读查询共用的职责。
- 增加只读与字段类型负例、初始化不读取、动态更新、默认预设、同名 schema 错误及独立请求单测。
- 真实 Vue/Svelte 夹具将 JS 读取值与浏览器样式对照，覆盖 SSR、hydration、父/子更新、null 重置、多主题、Teleport/DOM 移动与销毁重挂载。

本地 check/build、101 项快速测试、框架浏览器/SSR/HMR 与体积门禁已通过。原生 LSP 对 core 实现、类型夹具、Vue/Svelte 组件均 complete=true、errors=0。Svelte 官方检查器对新增主题模块和叶组件无问题；父测试夹具报告的直接 DOM 移动是刻意验证逻辑主题与 DOM 位置无关的既有场景，保留其显式清理，不作为普通应用用法推广。

独立消费者验证已通过：Vue/Svelte 分别安装 tarball，检查新导出与严格类型、官方 Vite 客户端/SSR 构建和 hydration；两套生产依赖审计均无已知漏洞。独占临时消费者和 HMR 项目已由测试清理，报告保留在忽略目录 test-results。

代码提交 `5f4efdb` 的 [完整 CI](https://github.com/kenconnet666/zerodep-css/actions/runs/35786867462) 七个 job 全部通过：Windows/Linux 基础检查、语言服务与独立类型负例、独立安装、Chromium/Firefox/WebKit 样式及框架回归。每个浏览器 job 同时覆盖 core 和框架套件；没有把本地 Chrome 结果当作其他引擎的证据。

readTheme 单函数保活产物为 3,395 字节，gzip 1,172 字节，新增 4,500/1,800 字节预算以防止主题查询意外带入整个 CSS 引擎。原有四个入口仍通过既有预算；这只是构建体积，不是运行速度承诺。

本轮完成两项实施提交：`0ebc647` 修复与整理，`5f4efdb` 主题 API 与集成验收；本记录随后以文档提交归档。审查覆盖配置/编译/主题 API 边界及测试资源所有权；本轮未改变序列化、CSSOM 事务和恢复协议，也未承诺流式 SSR 或新的编译优化范围。包版本仍为 0.2.0，变更记录列在未发布区，三个包继续 private。
