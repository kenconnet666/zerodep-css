# 运行时优先：基线与实施讨论

日期：2026-09-23。分支：codex/runtime-first。状态：方向已确认，下面的具体优化顺序为讨论建议，尚未实施。

## 已确认的产品合同

运行时 CSS 是正式能力，不是待删除的临时后备。编译、准备缓存、预计算和变量绑定只负责优化；不能为了优化而禁用原本合法的函数复用、同步控制流、真实作者继承或动态样式结构。无法证明等价时继续执行运行时路径。

保留普通 css 回调、Css/ThemeCss 两重继承、无 bx 的作者写法、根命名与 debug、全局样式/动画、SSR 请求隔离和宿主所有权。继续使用 Vue/Svelte 原生响应式。现有 API 仍遵守同步回调与生命周期约束，不表示任意异步行为也自动受支持。

优化器应区别“无法优化”与“作者代码本身非法”：前者继续运行，后者保留原有错误合同，不能吞错或改变未选分支的执行时机。

## 为什么选 2db10e3

- 是 feat/native-reactivity 的最新运行时完整节点。包含原生主题准备、固定 token 索引、注册事务解析复用、Vue 稳定准备函数及 Builder 按需初始化等已落地优化。
- 产品和基础设施目录与 c98995c 一致；后面的 7f011ab、2db10e3 只增加预计算/编译优先研究，不包含强制静态产品迁移。
- [远程 CI 成功](https://github.com/kenconnet666/zerodep-css/actions/runs/35830142412)。性能研究有同机对照和局限说明，不能把旧数字当作新方案性能承诺。
- 强制静态改造从后续提交开始。保留 codex/static-css，便于参考静态资产、编译边界、框架绑定和 M4 跨模块研究；不整体合并。

本分支额外保留已修复的 LSP 路径规范化、目录竞态和 compiler 目录监听，以及监听回归测试。它们不改变产品架构。

## 推荐的内部职责

```text
原生 JS 回调 / 辅助函数 / AppCss
    ↓
有序样式描述（保留声明、嵌套和元数据）
    ↓
运行时处理与缓存 → 宿主注册 / SSR → class 字符串

可证明的编译优化
    → 提前准备稳定描述、规范化 CSS 或规则模板
    → 复用同一宿主和错误合同
    → 动态值能安全绑定时交给框架，否则保留运行时
```

不增加第二套公开 CSS API，也不立即要求业务作者写 prepare/compile/execute。内部可以借鉴 ORM 的结构/参数分离和 Ajv 的准备结果复用，公开形态是否调整另行讨论。

## 分阶段建议

### R1：建立语义和性能对照

用既有 runtime 作为语义基准，对优化开启/关闭进行差分：普通函数与闭包、私有字段与 super、动态选择器/media、raw/token、简写/长属性/important、异常与未选分支、主题覆盖、全局资源、SSR 和 HMR。

分别记录 Builder/有序描述、键生成、序列化/解析、注册与浏览器更新成本。沿用 Vue/Svelte 两轮对照，区分首次使用、缓存命中、值变化、结构变化、持续新规则；计时不与其他构建并行。已有按需初始化、事务复用和主题准备不重复包装成新收益。

### R2：优化普通运行时热路径

优先针对新 profile 中确认的开销：描述分配、完整 JSON 缓存键、重复规范化和相同注册内容处理。任何更紧凑的键必须保留声明顺序、类型、空值、名称/debug、资源依赖和配置身份，不能仅凭短哈希当成内容等价。

不用函数引用缓存任意闭包，不池化携带用户状态的 Css 实例，不跨请求缓存业务主题或有效样式状态。通用路径仍然执行用户函数；框架派生缓存只在原生依赖合同内减少重算。

### R3：稳定结构预计算

参考历史规则模板原型，优先预计算静态系统关键字、固定值与已证明结构。将首次使用中能提前做的序列化/解析移到构建期，不把实际宿主注册、隐藏分支执行或资源挂载提前。

编译产物必须与 namespace/layers/format、作者类型、来源和当前宿主合同兼容；不兼容时走原路径。是否直接提取 CSS 文件，需要额外证明 ShadowRoot、nonce、SSR 清单和动态资源顺序，不直接照搬 M4 固定静态配置。

### R4：动态值、主题及派生类型

继续使用框架原生 computed/$derived。优先稳定主题结构和已知数值的准备复用；raw/token 的未知值、CSS-wide 和空值保持直接声明语义。不能为了减少新类名，把任意字符串无条件变量化。

派生类型优化须保留构造器、getter、私有状态和嵌套作者语义；只优化确实能证明的情况。是否增加显式“稳定描述”合同是可讨论选项，不作为预设前提。

## 本轮不做的承诺

- 不把预编译 class 字符串的拼接顺序视为 CSS 覆盖顺序。
- 不承诺所有动态值都不会产生新规则；通用运行时生成本来就有这项成本。
- 不在保留同步任意 CSS 生成和完整验证的同时，承诺解析器/元数据一定能全部移出浏览器。
- 不承诺缓存一开就等于零开销；命中前的构造与键生成仍需测量。
- 不把约 100 KB 的旧完整运行时大小视为不可优化，也不把几个轻量辅助函数的体积视为等价替代。

## 需要一起讨论的两个选择

1. 编译插件：建议 core 保持独立运行，Vue/Svelte 使用插件获取自动优化；不让未安装优化插件导致本来合法的运行时 CSS 失效。
2. 第一轮范围：建议先做 R1＋R2，再接规则模板优化。这样可独立改善不容易编译的真实用户代码，不把全部收益押在静态命中率上。

当前分支没有开始这些产品修改。讨论确认后按小阶段实现、差分验证、中文提交与远程 CI 交付。
