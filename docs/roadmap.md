# 后续路线

运行时优先的 P1—P6 已完成约定的生产范围；[2c51b0f 对应的九项远程 CI](https://github.com/kenconnet666/zerodep-css/actions/runs/35946894347)已通过。实现、已验证的版本与部署边界见[支持范围](support.md)和[生产记录](production.md)。以下是新阶段候选工作，不代表已承诺或已实现。

1. **当前浏览器性能基线已重测**。同一依赖锁与 Chrome，在 P4c 前/当前按正反顺序各跑两次，原始报告见[性能文档](performance.md)。Node 新类注册成本下降约 11%，但原生/Emotion 行也有浏览器波动，不能声称整页更新同比提速。自动变量仍保持规则数为 1；运行时生成全新值会持续增加记录。
2. **性能架构已定案**。动态 raw/token 的重复值判定已消除；窄范围 Node 探针有收益，尚无整页同比提速证据。[运行时架构决策](performance-architecture-decision.md)明确当前不引入泛化动态结构准备、函数身份缓存或 style 节点池。[框架缓存决策](framework-reactivity-cache-decision.md)确认 Vue/Svelte 已使用原生主题派生与全局样式订阅，库不再自动叠加逐元素 computed/$derived。有限值自动变量仍约为原生变量的 1.8—2.1 倍；只有真实应用出现明确瓶颈、且推荐跨模块用法与 SSR/浏览器语义均可完整验证时，才按决策记录的单次硬门槛重新评估。
3. **扩大实际消费覆盖**。项目推荐把 `createStyles` 放在独立 `styles.ts`，当前这一路径完整运行但通常不命中同 SFC 优化。选择真实应用组件作为样本，再决定是否做跨模块静态追踪。边缘运行环境、Nuxt 3、组件 HTML 流式 SSR 及框架版本升级应各自建立独立验收，不复用 Node SSR 的成功结论。
4. **准备公开发布时再单独做发布审计**。五包目前均为 private。发布需要确定包名与版本策略、适配器 peer 范围、公开导出和真实消费示例，并重新审核依赖、许可与安全修补的传播；当前 CI 通过不等于已具备对外兼容承诺。

性能决策不阻塞第 3 项真实消费覆盖；其结果若显示明确瓶颈，再按决策记录打开一个受限优化任务。普通 `if/else/switch` 与函数复用已经是运行时作者能力，recipes/variants 不是默认目标。
