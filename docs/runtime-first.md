# 运行时优先：基线与实施讨论

日期：2026-09-23。分支：codex/runtime-first。状态：方向已确认，下面的具体优化顺序为讨论建议，尚未实施。

## 已确认的产品合同

运行时 CSS 是正式能力，不是待删除的临时后备。编译、准备缓存、预计算和变量绑定只负责优化；不能为了优化而禁用原本合法的函数复用、同步控制流、真实作者继承或动态样式结构。无法证明等价时继续执行运行时路径。

保留普通 css 回调、Css/ThemeCss 两重继承、无 bx 的作者写法、根命名与 debug、全局样式/动画、SSR 请求隔离和宿主所有权。继续使用 Vue/Svelte 原生响应式。现有 API 仍遵守同步回调与生命周期约束，不表示任意异步行为也自动受支持。

优化器应区别“无法优化”与“作者代码本身非法”：前者继续运行，后者保留原有错误合同，不能吞错或改变未选分支的执行时机。

## 为什么选 2db10e3

- 是 feat/native-reactivity 的最新运行时完整节点。包含原生主题准备、固定 token 索引、注册事务解析复用、Vue 稳定准备函数及 Builder 按需初始化等已落地优化。
- 产品和基础设施目录与 c98995c 一致；后面的 7f011ab、2db10e3 只增加预计算/编译优先研究，不包含强制静态产品迁移。
- [远程 CI 成功](https://github.com/kenconnet666/zerodep-css/actions/runs/35830142412)。性能研究有同机对照和局限说明，不能把旧数字当作新方案性能承诺。
- 强制静态改造从后续提交开始。保留 codex/static-css，便于参考静态资产、编译边界、框架绑定和 M4 跨模块研究；不整体合并。

本分支额外保留已修复的 LSP 路径规范化、目录竞态和 compiler 目录监听，以及监听回归测试。它们不改变产品架构。

## 推荐的内部职责

```text
原生 JS 回调 / 辅助函数 / AppCss
    ↓
有序样式描述（保留声明、嵌套和元数据）
    ↓
运行时处理与缓存 → 宿主注册 / SSR → class 字符串

可证明的编译优化
    → 提前准备稳定描述、规范化 CSS 或规则模板
    → 复用同一宿主和错误合同
    → 动态值能安全绑定时交给框架，否则保留运行时
```

不增加第二套公开 CSS API，也不立即要求业务作者写 prepare/compile/execute。内部可以借鉴 ORM 的结构/参数分离和 Ajv 的准备结果复用，公开形态是否调整另行讨论。

## 分阶段建议

### R1：建立语义和性能对照

用既有 runtime 作为语义基准，对优化开启/关闭进行差分：普通函数与闭包、私有字段与 super、动态选择器/media、raw/token、简写/长属性/important、异常与未选分支、主题覆盖、全局资源、SSR 和 HMR。

分别记录 Builder/有序描述、键生成、序列化/解析、注册与浏览器更新成本。沿用 Vue/Svelte 两轮对照，区分首次使用、缓存命中、值变化、结构变化、持续新规则；计时不与其他构建并行。已有按需初始化、事务复用和主题准备不重复包装成新收益。

### R2：优化普通运行时热路径

优先针对新 profile 中确认的开销：描述分配、完整 JSON 缓存键、重复规范化和相同注册内容处理。任何更紧凑的键必须保留声明顺序、类型、空值、名称/debug、资源依赖和配置身份，不能仅凭短哈希当成内容等价。

不用函数引用缓存任意闭包，不池化携带用户状态的 Css 实例，不跨请求缓存业务主题或有效样式状态。通用路径仍然执行用户函数；框架派生缓存只在原生依赖合同内减少重算。

### R3：稳定结构预计算

参考历史规则模板原型，优先预计算静态系统关键字、固定值与已证明结构。将首次使用中能提前做的序列化/解析移到构建期，不把实际宿主注册、隐藏分支执行或资源挂载提前。

编译产物必须与 namespace/layers/format、作者类型、来源和当前宿主合同兼容；不兼容时走原路径。是否直接提取 CSS 文件，需要额外证明 ShadowRoot、nonce、SSR 清单和动态资源顺序，不直接照搬 M4 固定静态配置。

### R4：动态值、主题及派生类型

继续使用框架原生 computed/$derived。优先稳定主题结构和已知数值的准备复用；raw/token 的未知值、CSS-wide 和空值保持直接声明语义。不能为了减少新类名，把任意字符串无条件变量化。

派生类型优化须保留构造器、getter、私有状态和嵌套作者语义；只优化确实能证明的情况。是否增加显式“稳定描述”合同是可讨论选项，不作为预设前提。

## 本轮不做的承诺

- 不把预编译 class 字符串的拼接顺序视为 CSS 覆盖顺序。
- 不承诺所有动态值都不会产生新规则；通用运行时生成本来就有这项成本。
- 不在保留同步任意 CSS 生成和完整验证的同时，承诺解析器/元数据一定能全部移出浏览器。
- 不承诺缓存一开就等于零开销；命中前的构造与键生成仍需测量。
- 不把约 100 KB 的旧完整运行时大小视为不可优化，也不把几个轻量辅助函数的体积视为等价替代。

## 决策讨论记录

用户已确定的目标（尚未实施为新架构）：core 尽量薄，Vue/Svelte 适配器提供完整可运行方案；不再将 core 独立运行作为目标。运行时 CSS 始终是正式能力。

第一轮三个决策已全部确认：

1. 应用根部统一配置作者类型、默认主题等，组件避免重复配置；SSR 请求隔离和清理由适配器封装。
2. css 保留 class 字符串返回形态。编译器在能证明正确的使用点处理变量，其余保留运行时生成类名。
3. 编译插件可选，适配器本身提供完整功能；插件提供预计算、自动变量绑定和源码诊断等优化。

第二轮已确认：

4. raw 保留原生 CSS 值语义：检查声明结构边界，具体值是否有效交给浏览器，不因库内语法表落后而拒绝新语法；已知单位等 API 的参数错误另行校验。
5. 属性参数出现 null/undefined 时跳过整条声明，多参数不缩减为另一种含义；0 有效，false 不是通用省略标记。主题空值继承见第 13 项。
6. 提供组合能力，后面的相同属性覆盖前面的。
7. 按选择器和条件上下文分别组合：基础属性不删除 hover/media 等其他上下文的同名属性，相同上下文内按先后处理。
8. 简写与长属性遵循原生先后关系：后来的简写覆盖相关长属性，后来的长属性只修改对应部分。
9. 单次 css 回调、辅助函数写入和多个样式组合统一使用同一覆盖规则，不按声明来源区分。

10. 最终确认：同一上下文中，同一属性后写直接删除并替换前写，不考虑前声明是否带 important。先 color: red !important、后 color: blue，组合结果只保留 blue。此规则统一适用于第 10 项的所有来源；不再引入 important 的合并优先级例外。

作者层直接替换的语义后果：后写的 raw 值若被浏览器判为无效，不能回退到已经删除的同属性前声明；该值本身仍按浏览器原生规则处理。null/undefined 因为不产生声明，不应自行变成删除此前声明的操作。

第三轮已确认：

11. 组合统一沿用 css(base, override) 入口，从左到右处理，并允许混入样式回调；不增加 cx/merge 等平行 API。
12. 普通第三方 class 原样保留，仅本库掌握的样式参与属性合并；外部规则最终仍按浏览器层叠生效，不扫描外部样式表猜测声明。
13. 局部主题覆盖中的 null/undefined 都不形成局部覆盖，恢复父级继承；需要主题定义初始值时显式使用 defaults。此项替代旧基线中 null 重置 defaults 的行为，实施进度见 production.md。

第四轮已确认：

14. 项目建立统一样式入口（例如 styles.ts），配置 AppCss 并导出带作者类型的 useCss；组件从该入口导入，不重复配置类型，不依赖全局 TypeScript 类型声明。共享配置和入口，应用／SSR 请求分别持有运行状态。
15. 组件统一使用 const css = useCss()，直接返回样式函数；替换 useStyleRuntime，不保留同义入口。已实现于 createStyles 绑定入口；阶段验证见 production.md。
16. 未指定作者类型时默认系统 Css；需要内置主题关键字时显式选择 ThemeCss，用户可在任一层继承后于项目入口统一配置。

第五轮已确认：

17. 局部主题以 provideTheme 函数在组件初始化时设置，对当前组件及后代生效；按框架逻辑树继承，Teleport/Portal 不因 DOM 移动丢失主题，先不提供同义 ThemeProvider 容器。
18. 主题配置和局部覆盖接受静态对象或 getter；动态输入统一使用 () => 对象，内部读取 Vue ref 或 Svelte 响应式值，不自动解包 ref/store。
19. 使用内置 ThemeCss 时默认亮色，提供亮/暗预设；业务负责切换、跟随系统及偏好持久化。自行继承 Css 的项目完全自行安排主题。

第六轮已确认：

20. 普通 css 样式与其引用的共享动画跟随应用／SSR 请求存活，组件卸载不删除；应用销毁或请求结束统一清理，类名可在同一应用内复用。计算缓存淘汰与已注册规则生命周期分别处理。
21. 组件声明的全局样式由声明组件自动管理，挂载期间生效，更新自动同步，卸载自动释放；全应用样式在根组件声明。
22. 首版生产验收覆盖完整字符串 SSR：完整渲染后统一输出样式与恢复信息；请求隔离、收集、hydration 和清理由适配器封装。流式／异步分块 SSR 明确列为后续能力。

第七轮结论与后续确认：

23. 用户确认 TS 为主要约束，不重复进行重型类型或 CSS 值语法检查。仅保留 NaN/Infinity、异步回调和失效宿主等必要的最小运行时检查，开发和生产均明确报错，本次调用不留下部分注册结果。
24. 规则增长策略尽量宽松，可配置上限辅助诊断持续增长。按此方向拟定默认无硬上限，开发增长提示去重、避免刷屏，只有应用显式配置硬上限时拒绝新增规则；不将增长直接判定为泄漏，不自动删除仍可能被使用的规则。
25. 诊断采用按需详细模式：开发保留可读命名与源码位置，默认只提示错误和资源增长，开启 debug 才展示优化未命中等详细原因；生产默认关闭来源信息。

第八轮已确认：

26. 同 key 全局样式内容相同时共享，不同时报告冲突；最后一个声明者卸载时释放共享样式，不采用依赖挂载顺序的覆盖栈。

    P3 实施边界：内容指规范化后的序列化正文与动画依赖，不猜测任意 raw token 的语义等价。多 owner 存活时只接受与当前内容相同的更新，剩单 owner 才可改变内容。因此即使多个 owner 在同一 tick 想改成相同新值，也会同步报告共享冲突；动态全局应在根组件声明一次，或使用不同稳定 key。该边界避免额外调度器和框架 flush 外的异步错误，保留同步事务与 SSR 语义。

27. css 组合支持有序数组展开和 false/null/undefined 空项，但它们只是便捷写法。文档和示例优先推荐普通辅助函数及 if/else/switch，说明复杂的条件数组通常不如原生控制流直观；不为此增加运行时警告或将便捷写法标记为弃用。

第九轮已确认：

28. 首版支持 Vue 3.5 与 Svelte 5，不增加旧框架兼容目标；实施时明确并验证最低支持版本和锁定版本。
29. 在 Chromium、Firefox、WebKit 验证库机制；具体 CSS 特性由浏览器决定，不内置通用前缀、polyfill 或语法降级。
30. 首版新增 Nuxt、SvelteKit 两个正式适配包并完善接入和验收，不能只提供示例后列为后续工作。计划包名为 @zerodep-css/nuxt、@zerodep-css/sveltekit，复用对应框架适配器，负责根配置、SSR 请求隔离/样式输出/恢复、路由切换和 HMR。第 22 项完整字符串 SSR 边界仍适用。

当前官方 npm 元数据（2026-09-23）：Nuxt 4.5.2、SvelteKit 2.70.3。官方集成点已核对：Nuxt 模块/运行时插件及 app:rendered；SvelteKit handle/resolve/transformPageChunk。钩子可行性不等于适配已实现；具体请求传递和收集时机须经真实项目验证，不能在模块级共享可变请求状态。

最后一轮已确认：

31. Nuxt 4＋SvelteKit 2，与 Vue 3.5／Svelte 5 组成首版矩阵，不额外承担 Nuxt 3 兼容。
32. 首版完整验证 Node 服务端 SSR 和静态预渲染；Cloudflare Workers 等边缘运行环境后续专门验收。
33. 不承诺等于原生 CSS。实施过程中适当做性能诊断与优化，以证据选择合适方案；不预设硬性能门槛。

用户已授权进入目标模式，持续执行全部阶段直到约定范围生产可用。遇到明显困难可以适当调整决策，保留调整理由；坚持代码简洁、维护性、目录命名整理及适当中文注释。执行计划与阶段证据见 [生产实施记录](production.md)。
