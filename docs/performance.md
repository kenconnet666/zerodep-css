## 结论与取舍

在 1,000 行连续值场景中，bx 的总更新时间约为手工变量参照的 1.55 倍（Vue）和 1.46 倍（Svelte）；仍有差距。相对本次 Emotion 样本，bx 分别减少约 40.3% 和 45.1% 的总更新时间。不能据此宣称所有 CSS 场景都优于 Emotion。

普通 runtime 的挂载成本更低，适合静态或有限状态；持续出现的新值会累积不同内容的类。bx 的首次挂载需要建立私有值规则，但连续值更新保持规则数量稳定。本轮保留平铺片段缓存：1,000 行时关闭缓存的更新时间略高，200 行会有小幅反向噪声，不为争取某一次计时引入复杂字符串结构。

Svelte 使用原生模板派生；Vue 的模板缓存对无关状态更新有帮助。框架间调度机制不同，分别记录结果，不混成一个排名。常量 bx 仍输出变量，但不创建不必要的订阅。
