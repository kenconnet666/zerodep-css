# 主题树实施方案

状态：2026-09-23 无人值守生产化阶段的实施决策，尚未作为已实现 API 交付。用户已授权自主决策和推进，不再等待额外确认。

## 作者与所有权

- 保持真实 `class AppCss extends Css`；派生 getter 使用 `extendProperty` 将主题 token 加到系统属性类型上，系统属性仍是不可调用对象。
- core 提供冻结的 `defineTheme(name, defaults)` 定义，包含类型化 token 树、默认值和继承默认值的 `extend(overrides)`。预设继承沿用同一组变量标识，覆盖值不进入 token 身份。
- token 使用 CSS 变量引用并携带默认 fallback；没有主题 provider 时依然可用。默认值与定义不持有 runtime、组件或请求状态。
- Vue/Svelte 提供 `provideTheme(definition, overridesGetter)`。覆盖计算用各框架原生响应式；父级作用域按组件上下文传递，子级只覆盖自己提供的字段。
- provide 返回作用域，当前组件可以显式传入 `useStyleRuntime(context?, themeScope?)`；后代默认继承。避免让 Vue provide 的后代语义与当前组件语义混淆。

## 覆盖和输出

- undefined 表示继承，null 表示重置到当前定义的默认值，对象表示递归局部覆盖。拒绝未知字段、循环结构和不合法叶值，使用冻结快照阻止外部修改。
- 每个有效主题生成可复用的变量声明类，样式 runtime 的视图在 css 返回值中附加它。所有具有框架样式的元素都携带逻辑作用域的有效主题，因而 Teleport 或其他 DOM 移动不会丢失主题。
- 所有权仍属于应用/请求 runtime。子 provider 只拥有自己的响应式派生，不 dispose 共享上下文、不删除其他元素仍引用的类。
- 同一主题有效值复用变量类；主题变化不重新生成引用 token 的每份 CSS。频繁普通值继续使用编译器的元素变量路径。
- SSR 输出变量类和样式清单，客户端用相同定义及覆盖恢复。不同请求的覆盖、缓存和主题状态不能共享。

## 必需验收

1. 根默认值、部分覆盖、多层覆盖、null 重置及兄弟隔离；预设继承后的变量标识稳定。
2. AppCss 自定义关键字的类型、嵌套派生 getter 与运行时一致；未知主题字段和错误叶类型具有负例。
3. 父主题更新、子局部更新、卸载和重新挂载；变化不会重建每个 token 样式的内容或破坏全局槽位。
4. 真实 Vue/Svelte 客户端与 SSR/hydration、两个请求并行、Teleport/DOM 移动，及独立安装与官方插件构建。
5. 主题失效输入、主题定义与覆盖对象被外部修改、同名不兼容结构等失败路径明确拒绝。

本阶段不引入 recipes/variants，也不把复杂条件或主题值处理强制改造成静态编译器专属能力。编译器可以继续优化可证明稳定的部分，运行时路径保持完整。
