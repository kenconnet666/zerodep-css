# 系统属性延迟注册：实施与测量

本阶段保留 `s.color.red` 的声明字符串、两层主题继承和运行时 `css(...parts)`。生成器现在把 502 个系统属性 getter 的注册放到首次 `new Css()` 中；属性关键字仍在首次访问该条属性链时创建。模块只导入 `ic()` 或直接使用 `ColorCss` 时，不再执行或携带完整 `Css` 的注册代码。

| 消费端只用到          | 改动前压缩 JS | 改动后压缩 JS |
| --------------------- | ------------: | ------------: |
| `ic()`                |     577,763 B |          98 B |
| `new ColorCss().red`  |     577,700 B |       6,131 B |
| `new Css().color.red` |     577,707 B |     577,758 B |

这是用当前构建出的包入口再经 esbuild 打包得到的字节数。直接使用完整 `Css` 的包仍需完整作者模型，这次改动只解决未使用作者模型时的按需打包。

在 Chrome 153 的五轮交错新页面探针中，完整作者包的脚本求值中位数约从 18.7 ms 变为 13.3 ms，首次 `new Css()` 从约 0.1 ms 变为 6.8 ms；第二次构造都接近测量分辨率下限。工作主要从模块求值移到了首次构造，**不能宣称完整作者路径的首次使用更快**。这些是本机短时探针，不是跨设备性能承诺。

另一个已构建入口的冷加载探针得到 `core` 导入执行中位数 18.6 ms；旧阶段记录约 22.0 ms，但两次运行环境与浏览器热状态不能严格配对，不据此下性能结论。Vue/Svelte 的浏览器、Node SSR、hydration、包类型消费和两层主题继承焦点测试通过。远程 CI 负责最后的 Windows／Linux、LSP 与集成回归。

同阶段还用生成器为全部 502 个 `Css` 系统字段输出 JSDoc。WebStorm Quick Documentation 对 `s.display`、`s.fill` 能显示中文说明和链接；发布声明文件保留这些文档。源码汇总文件约从 69 KB 增至 143 KB，`.d.ts` 约从 27 KB 增至 104 KB；仅增加注释时，压缩 JS 的哈希与原产物相同。用户覆盖的主题字段文档仍由用户自己负责。
