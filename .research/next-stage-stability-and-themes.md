# 下一阶段：运行稳定性、调试与主题体验

状态：已按五阶段实施，结果与保留边界见[交付记录](stability-and-theme-delivery.md)。本文保留原规划；本轮基线为 `909d262`，不将超出矩阵的发布 / 部署场景视为已经验收。

## 保持的方向

- 运行时 CSS 是基础；隐式绑定是可选优化，保留普通 JS、字符串片段和运行时回退。
- `css` 统一组合声明和当前宿主已登记的类，返回一个类名；独立 `cx` 不恢复。
- 选择器是 `s._hover`、`s._active`、`s._selector` 等下划线方法；独立 `ic` 不恢复。
- `keyframes`、`globalCss` 保持现有登记职责；不增加同义 API。
- `Css` 保持系统能力；主题和用户扩展通过类继承组织，不强加 recipes / variants 或公开 var 方法。
- 五包保持 private。公开发布、流式 SSR、边缘部署、Shadow DOM 不放进这一轮。

## 1. 先统一语义与文档

近期连续调整了 css 组合和选择器入口，需要先检查整个作者流程，而不是继续扩大 API 数量。

重点用例：声明数组与辅助函数、已登记类组合、选择器嵌套、响应式值、结构分支、主题属性覆写。Vue / Svelte 各覆盖模板内调用、setup / 实例脚本初始化和派生求值，区分隐式变量更新与普通 JS 的执行时机。

例如下面的区别需要以示例和测试固定：

```ts
// 可识别的 width 响应式值由插件绑定。
const box = css(s.width.px(width.value));

// 条件仍是普通 JS；在 setup 中执行一次，不自动变成结构订阅。
const initial = css(enabled.value && s.color.red);

// 在模板调用此函数，让框架根据状态重新选择结构。
function currentClass() {
  return css(enabled.value ? s.color.red : s.color.blue);
}
```

不为了抹平区别而把任意函数、if/switch 或 const 初始化都改造成订阅。复核导入别名、变量遮蔽、自定义覆写、嵌套辅助函数与纯字符串加工，防止误转换。发现真正的语义问题先复现再修复；合理的回退保留并明确说明。

文档以 `docs/` 为当前使用入口，`.research/` 留存原始测量和决策，不重复维护多份现行指南。已发现 `docs/minimum-usage.md` 开头仍称绑定、全局规则、动画和 nonce 未提供，`docs/framework-examples.md` 也有过时的 CSP 状态，需要修正。此类文案问题不应被当成产品尚未实现。

验收：常用写法在两框架的输出与更新时机有明确断言；当前文档没有互相矛盾的状态、失效命令或未标明历史的旧 API 示例。

## 2. 生命周期与真实 HMR

当前已确认：列表 frame / key 缓存保留到所属组件卸载；普通类与动画由宿主长期缓存。持续更新已有变量不增加规则，不等于反复挂载或无限更换列表 key 也不增长。先用探针分别测量，而不是把全部增长一律认定为泄漏。

用例包括：

- 连续挂载 / 卸载含隐式绑定的组件，检查订阅和私有值规则是否回到基线。
- 同一列表不断替换 key、删除再插入、重排和嵌套循环。
- 反复进入 / 离开 Nuxt 和 Kit 页面，区分静态类复用与实例私有类增长。
- 真正 Vite 开发服务中的模板热更新、脚本热更新、删除声明和修改选择器。
- 热更新或卸载一个组件时，另一个实例和兄弟子树保持正确。

先利用框架生命周期释放可以证明结束的订阅和私有资源。`css()` 返回的字符串可能被外部保存和复用，不能仅因缓存较旧、当前渲染没访问到或达到数量阈值就删除普通类。不要直接上 LRU 删除、全页面 MutationObserver 或一套复杂引用计数。若某项清理无法在现有字符串契约下证明安全，保留它并提供统计和推荐的组件生命周期边界，单独说明代价。

验收：组件已结束的订阅 / 私有值规则没有遗留；HMR 不产生错误覆盖和重复活动订阅；长期保留的缓存有明确分类、所有者与测量结果。不设置与机器性能强绑定的时间阈值。

## 3. 让诊断可以直接定位到作者代码

当前编译提示能指出文件和回退原因，运行时覆写提示主要包含方法名。下一步优先补文件、行列和调用片段，让作者能知道是哪一次 `css` / `_selector` 未被优化。

建议输出含义：`Card.vue:18:9，用户覆写 _hover，此片段保留运行时求值`。这是诊断格式示意，不是新增公开函数。

核对 source map 在 Vue/Svelte 实际开发工具中的定位。必要时扩展现有 `cssStats()`，区分普通类、动画、全局块和私有值规则；不另增一组同义统计入口。开发定位数据不进入生产的高频调用路径，不因此更换生产类名算法。

验收：故意构造的回退与错误可以定位回原组件；生产构建不携带仅用于诊断的完整源码 / 开发记录，也不持续收集调试日志。

## 4. 两层继承的主题体验

当前 `core/examples/theme.ts` 已有两个简单主题的示例，但它们只是示例数据，不能称为完整系统主题预设。

建议形成可选的亮 / 暗语义主题，优先覆盖背景、表面、文本、次要文本、边框、强调色、成功 / 警告 / 错误和交互态。预设不进入纯系统 `Css` 的必需依赖，不新建第六个包。

保持两种自然扩展方式，以下是目标形态：

```ts
class AppCss extends Css {
  // 用户完全自行安排主题。
}

class AppCss extends ThemeCss {
  // 继承可选预设后继续扩展；ThemeCss 在这里是拟定名称。
}
```

主题关键字通过对应属性类继承扩展，使用时仍是 `s.color._text` 等字符串字段。主题值通过原生 CSS 自定义属性向下继承，优先用已有 `css` 类切换承载作用域，避免另外引入响应式主题存储或手工内联 style 的必需条件。不要求用户逐个声明变量绑定 API。

先在 Vue/Svelte 各做一个完整组件样板，再确定预设导出、主题作用域接入和最少的必要封装。新的公共名称及示例需要在实现前明确，不从历史研究稿直接恢复旧 API。

验收：系统类独立可用；预设可选；父级主题影响后代，子树覆写不影响兄弟，撤销后恢复继承；SSR 首屏、hydration 和样式 CSP 配置一致。Teleport / portal 单独记录物理 DOM 边界，不承诺自动保留原位置的主题继承。

## 5. 根据以上探针优化并收敛目录

性能重点由拼接微基准转向实际成本：首次挂载、200 / 1,000 项列表更新、反复挂卸、主题切换和无关状态更新。分别记录 JS、布局读取、规则数、活动绑定数量与保留资源，不只比较一个总耗时。

保留手工 CSS 变量、普通运行时 CSS 和 Emotion 对照；只优化能在真实框架路径复现的热点，例如重复值未变仍写 CSSOM、重复的选择器关联、临时数组和不必要的作用域登记。保持同步路径与回退，不为此添加 Worker / SIMD 或 CSS 解析层。

把已经成为 CI 门槛的稳定测试按核心、框架、元框架职责整理；纯研究微基准与原始结果仍留在 `.research/`。仅迁移边界已清楚的文件，不机械拆分成很多小模块，不移动只为产生目录变化。测试命令、CI 和文档链接必须同时更新。

验收：行为正确、无不合理的资源增长；优化有对应前后数据，无法证明收益的复杂实现不保留。历史性能样本继续注明对应提交和机制，不当作新实现的实时数据。

## 执行与交付顺序

建议按五个可审查的阶段执行：语义和文档 → 生命周期 / HMR → 诊断 → 主题样板与预设 → 性能收敛和目录整理。前面复现的正确性问题优先修复，不被后续 API 扩展打断。

每阶段中文提交并推送；本地运行与改动直接相关的检查，包出口或基础配置变化运行 `pnpm check`，完整跨平台、浏览器、SSR 和元框架矩阵由远程 CI 完成。性能测量不与其他重负载测试并行，以免数据相互干扰。报告中区分通过、明确回退、未验收和仍待设计。
