# 组件性能复测与下一阶段建议

日期：2026-09-26。承接[字符串拼接研究](string-concatenation-research.md)和[框架结合研究](vue-svelte-runtime-integration.md)。

实施更新：下文规划的可执行组件、Node SSR/hydration 和子树主题验证已落实，入口见[框架用法示例](../docs/framework-examples.md)。后续也已完成[Nuxt/SvelteKit 的 Node SSR 与预渲染接入](../docs/metaframeworks.md)；本页保留形成决策时的性能记录。

## 本轮决定

保留产品注册器的 `join('')`。`+=` 在短字符串注册器微基准中有优势，但真实组件更新没有表现出跨负载的稳定收益，不值得据此改动默认实现。继续保留该候选，本阶段停止扩展拼接、Worker、SIMD 和编译提取研究，转向框架使用体验与生命周期验收。

没有引入依赖、修改作者字段、改变 `css(...strings)` 或新增响应式 API。测试中的 `loop` 只是内存构建变体。

## 组件实测

运行 `pnpm --dir test/tools probe:concat-components`；用环境变量 `MUP_ROUNDS=5` 得到本轮配置。两次独立运行，每次 Vue/Svelte 各 5 轮，使用生产编译、200 个元素，每个样本打开独立页面，轮换执行顺序。两个候选都显式解析到当前 core 源码，只替换拼接语句，并断言替换恰好发生一次。框架用固定的 Vue 3.5.43、Svelte 5.57.0，Chrome 153.0.8010.54。

计时包含状态更新、框架刷新和布局读取。有限值在 16 个宽度之间切换 30 次；新值场景更新 5 次，每次产生 200 个新宽度。它们不能横向比较总时间。挂载、无关状态更新、规则数、调用数和逐元素计算样式也分别记录或断言；性能时间没有硬门槛。

两次运行各取 5 轮中位数，单位毫秒：

| 场景                     | 首轮 join | 首轮 += | 复测 join | 复测 += |
| ------------------------ | --------: | ------: | --------: | ------: |
| Vue，有限值直接调用      |      44.5 |    59.7 |      46.0 |    42.6 |
| Vue，持续新值直接调用    |      30.2 |    31.4 |      29.5 |    27.3 |
| Svelte，有限值直接调用   |      54.3 |    45.5 |      51.1 |    47.4 |
| Svelte，持续新值直接调用 |      27.1 |    27.6 |      27.1 |    28.6 |

Svelte 有限值两次都改善，但 Vue 胜负反转，新值场景也未统一改善。类表和变量组在更新期间不再调用注册器，两个拼接候选的这些对照组仍出现计时差异，说明不能把所有时间差都归因于拼接。样本未覆盖移动设备、Firefox、WebKit、堆分配与大规模真实页面。

比毫秒更明确的是工作量变化：

| 行为                                | Vue 直接调用 | Svelte 直接调用 | 两框架的类表 / 变量路径 |
| ----------------------------------- | -----------: | --------------: | ----------------------: |
| 有限值场景 20 次无关更新的 css 调用 |        4,000 |               0 |                       0 |
| 30 次有限值更新的 css 调用          |        6,000 |           6,000 |                       0 |
| 新值场景 5 次更新的 css 调用        |        1,000 |           1,000 |              变量路径 0 |

新值场景的初次渲染、预热和测量后，直接调用累计 1,400 条规则，变量路径始终 1 条。有限值类表为 16 条。变量路径在这轮有限值负载下比直接类切换更慢，不能统一把所有值都改成变量。

原始结果：[首轮](../test/tools/results/concat-components-a.json)、[复测](../test/tools/results/concat-components-b.json)。两轮所有浏览器正确性断言通过；不代表 Nuxt/SvelteKit 或所有 SSR 场景已验收。

## 静态部分复用

另外运行 `pnpm --dir test/tools probe:static-prefix`。使用当前未改动的注册器，7 个静态声明加 1 个动态宽度，16 种组合，预热后 7 轮轮换顺序，下面是 100,000 次读取的中位数：

| 路径                                      |    耗时 |
| ----------------------------------------- | ------: |
| 每次传入 8 个声明字符串                   | 33.1 ms |
| 静态 7 个声明提前拼好，每次传入前缀和宽度 | 24.6 ms |
| 初始化时注册完整组合，之后只读取类名表    |  1.2 ms |

三种路径验证了相同类名、相同声明顺序且只有 16 条规则。该探针只测 JS 调用，不含 DOM、框架刷新及首次注册；类表成本不能外推为整个组件加速倍数。原始记录见[静态前缀样本](../test/tools/results/static-prefix.json)。

这些写法现有 API 已支持，不必增加缓存库：

```ts
const s = useCss();
const base = s.display.flex + s.alignItems.center + s.color.red;
const small = css(base, s.width.px(24));
const large = css(base, s.width.px(48));
// 已知状态只选择 small / large；开放动态值继续 css(base, s.width.px(value))。
```

完整类名只在当前组件 / SSR 请求的活动宿主内注册。不要通过模块级全局类名表绕开请求隔离，也不要改变原有声明顺序，把分散的静态声明强行挪到一起。

## 推荐的下一阶段：固化框架用法，先不增加公共 API

### 1. 做两套可运行的组件示例

Vue/Svelte 分别覆盖静态样式、少量条件状态、开放动态值、连续值变量绑定和 `ic()` 的 hover/media 分支。保持 `useCss()`、`css()`、`raw()`、`px()`、`ic()` 名称，不另造 `computedCss`、`derivedCss` 等同义入口。

有限状态使用初始化时注册的完整类名，通过纯 `computed` / `$derived` 选择；派生表达式只读状态，不注册规则。直接运行时分支仍保留，复杂或稀疏分支不必预枚举。已有 `memo` 性能夹具包含有副作用的派生表达式，只是研究对照，不作为正式用法复制。

把上述示例提升为文档与测试共用的夹具，避免正式文档和可执行代码长期分叉。验收无关更新、分支切换、逐元素变量、最终计算样式与规则数；不以跨机器毫秒百分比设门槛。

### 2. 同一批示例验证 SSR 与 hydration

覆盖首屏静态类、有限状态初始分支、服务端输出变量初值、客户端首次恢复和后续更新。并发请求使用不同作者实例和变量初值，确保没有规则或主题数据串请求；预热后重复切换不应不断增加规则，变量更新应保持规则数稳定。

服务端首屏已经带上正确样式，不依赖浏览器 effect 补注册；hydration 恢复既有规则后不重复写入。这里复用已有 host，不增加第二套注册时序。

### 3. 再做子树主题的小范围验证

保留 `class AppCss extends Css` 和属性链子类扩展。用原生 CSS 自定义属性验证“父级主题、子树覆盖、兄弟隔离、亮暗切换、hover 变量继承”，让类关键字引用稳定的 `var(--...)`，具体变量值由框架绑定到对应 DOM 边界。

类继承负责关键字与类型，DOM 继承负责实际变量值；不假设重新 provide 一个普通实例会更新已挂载后代。第一步先用原生 `style` / Svelte style 指令，不新增主题框架或必需编译器。发现反复出现的实际接入成本后，再讨论是否需要很小的辅助 API。

这三项完成后，下一批再接 Nuxt 4 / SvelteKit 2 的 Node SSR、客户端恢复和预渲染。它们当前仍只是预留包，不能与本轮已经验证的 Vue/Svelte 底层原型混为完成。

## 交付边界

性能研究轮次只完善研究脚本、保存结果和更新规划。后续实施已增加 `core/examples`、`vue/examples`、`svelte/examples`，文档与测试共用同一份组件；浏览器与并发 Node SSR/hydration 用例已接入 CI。产品 API、`join` 注册器和生成属性链未改动。

本地 `pnpm check`、Vue/Svelte 浏览器焦点用例及两套新示例验收通过。测试构建现在统一 Vue/Svelte 运行时解析，避免包内示例和探针驱动各加载一份 Vue 响应式运行时。保留用户的 `core/test/types/theme.ts` 未提交修改；完整跨平台与集成验收以各提交的远程 CI 结果为准。
