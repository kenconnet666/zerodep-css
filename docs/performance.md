模板元素变量相对同模板样式表变量，总更新时间减少约 21.0%（Vue）和 22.0%（Svelte）。但相对手工变量仍慢约 33.4% / 26.0%，尚未达到相同性能。Emotion 使用锁定的 @emotion/css 11.13.5，输入同样的作者声明；结论仅覆盖这个连续值场景。

Vue 元素路径的无关更新时间反而增加：51.1 ms 对 30.0 ms。关闭 class 缓存的元素版本为更新 162.3 ms、无关更新 42.5 ms，未显示当前缓存对这一特定负载有收益。后续应单独分析作者身份检查、style 求值/补丁和 class 缓存成本，不把减少规则数等同于每个维度都提速。Svelte 的无关更新仍很少。

元素变量把每行的值保存在 DOM，表中不将内联值算作样式表规则；1 条规则不等于没有每元素存储。普通 runtime/Emotion 在本用例中不断得到新值，所以类数增长；有限状态会复用内容缓存。

## 验证和使用建议

- 静态或有限状态可继续普通 css；连续值使用 bx。保持原生 if/switch，不额外建状态 DSL。
- 优先复用作者实例和已存在样式。缓存命中不重新哈希或插入 CSSOM；不为短声明默认引入 Worker、Wasm/SIMD 或多级片段缓存。
- 模板 bx 的每行值已转入元素；脚本辅助函数、setup 或派生回调中的 bx 仍可能使用私有样式表路径。两条路径和 CSP 配置见[绑定文档](bindings.md)。
- CI 保留同模板两种传输、Vue 缓存开关、手工变量、普通 runtime、Emotion 对照；不设置计时硬门槛。正确性、规则数量和资源清理单独断言。
- 当前核心覆盖率不能代表框架编译器和浏览器总覆盖。源码 LCOV、三浏览器、HMR 和元框架任务各自提供证据。
