# 编译期 CSS 主架构研究

> 历史研究：下文记录当时的实验与建议。2026-09-23 最新决定是保留完整运行时 CSS，编译为优化手段；当前实施讨论见 [运行时优先方案](runtime-first.md)。不要将本研究的旧主路线建议作为当前指令。

2026-09-23，基线 7f011ab。本轮只新增研究探针与文档，没有修改产品架构。结论：对本项目以组件样式、静态主题、条件分支和响应式值为主的使用场景，编译期产出 CSS、框架负责类名/变量更新，比继续让通用样式引擎驻留浏览器更值得作为主路线。

这不是声称能把任意 JavaScript 无损编译成 CSS。需要明确动态 raw、跨组件动态绑定、派生类行为、全局样式生命周期和无法分析代码的合同。

## 性能对照

探针 `.research/performance/compile-first.mjs` 使用真实 Vue/Svelte 官方编译器、当前运行时及已有编译插件。提取路径由夹具在构建阶段生成目标 CSS/类名/变量代码，尚未实现通用源码转换器；它验证可达到的执行成本，不代表新的编译框架已经完成。

Node 24.12.0、Chrome 153.0.8010.52；192 个元素，预热 5 批后计时 30 批更新，7 轮交替次序取中位数。静态场景 64 个不同样式；条件场景 2 个 if 状态 × 3 个 switch 状态；主题场景使用当前完整 lightTheme/darkTheme 的全部变量与相同变量名，逐元素切换主题类。没有用只切根节点的方案替代旧路径，也没有只给提取路径留下两个简化 token。

三条路径含义：

- runtime：当前运行时。静态场景已有稳定 prepareStyle；其他场景保留普通回调和原生主题缓存。
- optimized：静态场景使用上一轮规则模板原型；动态数值使用当前正式编译插件的自动变量路径；if/switch 和派生主题仍回退当前运行时。
- extracted：没有样式引擎的目标代码，静态 CSS 加字符串类名/原生变量绑定。数值保留有限性与非负范围校验。主题 CSS 在构建时由完整预设生成。

### 首次挂载

| 框架   | 当前静态准备路径 | 规则模板原型 | 完全提取 |
| ------ | ---------------: | -----------: | -------: |
| Vue    |          19.7 ms |       5.9 ms |   2.1 ms |
| Svelte |          20.0 ms |       6.6 ms |   2.1 ms |

完全提取在挂载前另有约 0.2 ms 的 CSS 激活成本：CSS 文本已经在内存中，本轮插入一张样式表并刷新布局。这不是 HTTP 冷加载时间。若加上这一项，本探针约为 2.3 ms；不能据此声称整页加载快 8～9 倍。JS 下载/首次解析、真实 CSS 文件加载和 FOUC 未测量。

### 更新耗时

| 场景                      | Vue 当前路径 → 提取 | Svelte 当前路径 → 提取 | 当前路径的口径                |
| ------------------------- | ------------------: | ---------------------: | ----------------------------- |
| 动态数值                  |        70.4→59.3 ms |           70.1→52.6 ms | 正式自动变量路径              |
| if/switch                 |       114.7→33.3 ms |          110.2→36.3 ms | 当前无法自动分析的运行时回调  |
| 亮暗主题                  |       161.8→24.8 ms |          199.7→26.5 ms | 完整预设 + 原生响应式主题缓存 |
| 静态 class 随无关状态更新 |          7.6→1.9 ms |             0.4→0.4 ms | 当前稳定准备函数              |

数值变量仍要写 style、自定义属性并触发样式计算/布局，没有数量级收益。本轮旧路径对旧路径控制组中，Vue 动态值更新为 64.5～83.3 ms，波动较大；不能把 15.8% 的差异当作稳定承诺。Svelte 对应控制为 63.7～69.5 ms。分支与主题差异更大，但只说明所测有限状态、完整预设场景，未涵盖动态主题覆盖与任意 raw。

Svelte 本来就不会因无关状态更新重复计算静态 class，因此此项更新不存在可宣称收益。两个 optimized 分支/主题场景实际仍是原路径，数值差异主要用于观察模块/JIT/环境波动。

### 体积

静态夹具的 gzip 字节，包含各自框架：

| 框架   | 当前 JS | 规则模板 JS | 提取后 JS | 提取 CSS |
| ------ | ------: | ----------: | --------: | -------: |
| Vue    | 127,855 |     129,094 |    26,140 |      961 |
| Svelte | 122,279 |     123,579 |    20,764 |      961 |

提取后 JS+CSS 合计比当前样本减少约 101 KB gzip。esbuild metafile 验证提取 bundle 不含 core/src 或 css-tree。这个差值来自删除整个通用运行时依赖，不只是减少几个函数调用；真实产品还需加回轻量主题 context、变量格式化和诊断辅助代码，不能把样本体积当作发布包承诺。多个页面共享依赖时也不能逐页重复累加这 101 KB。

编译过程、产物体积与运行时收益要一起评估：本轮没有建立生产级 CSS 资产分块/去重器，也没有测完整工程冷构建/HMR 耗时。

## 关键字与主题树

标准属性、关键字、单位、范围规则本来就来自生成数据，适合作为编译器输入；浏览器只需要用到的少量动态值格式化规则，不需要整张 Builder 元数据表。

静态主题树可编译出固定 token 名、主题 CSS 类与可供业务读取的 JS 常量。亮暗切换选择已有主题类，动态局部覆盖只更新既定变量。普通全局场景可利用 CSS 继承，但当前逻辑主题作用域不能直接降级成纯 DOM 祖先继承：Teleport/Portal、插槽和局部覆盖仍需 Vue provide/inject 或 Svelte context 传递主题身份，并在实际宿主应用主题类/变量。

本轮主题提取测了固定完整预设选择，没有实现生产级逻辑作用域适配器。保留一个很小的原生响应式适配层是合理的，这不等于保留运行时 CSS 生成器。

现有 ThemeCss 的 extendProperty + 静态 token getter 可以考虑识别为编译模式；任意用户 getter、构造函数、私有状态和继承链并不天然静态。需要区分「保持 class 作者语法」和「支持任意真实类的运行时行为」，不能承诺两者在纯编译模式下完全等价。

## if/switch 可以怎样编译

关键是运行时只判断条件，不在运行时重新构建样式。保留 if/switch 的控制流、条件求值次数、分支守卫与 switch fallthrough，把分支中的声明转换成已生成样式的激活标记。

少量有限状态可以生成完整组合。本轮 2×3 状态只需 6 个类，直接选择已有类名。不过 10 个独立布尔条件有 1,024 个组合，不能默认做笛卡尔积展开。

更通用的候选是按照原声明位置生成条件片段。例如：

```ts
css((s) => {
  s.padding.px(4);
  if (active) s.padding.px(8);
  s.paddingLeft.px(2);
});
```

可生成类似以下的 CSS 与运行时状态类选择：

```css
.site {
  padding: 4px;
}
.site:where(.active) {
  padding: 8px;
}
.site {
  padding-left: 2px;
}
```

`:where` 不增加优先级，按原顺序输出可保留此例的简写/长属性覆盖。浏览器探针验证 active 时 left 为 2px、right 为 8px。[Selectors Level 4](https://www.w3.org/TR/selectors-4/#zero-matches)

这只是局部示例证明，不是完整条件编译器。还需处理嵌套 selector/media、important、多处赋值、fallthrough、组件组合和多 chunk 顺序。class 字符串中把哪个名字写在后面，并不能决定 CSS 层叠顺序。

带动态值的分支必须保留守卫。例如 `if (row.detail) s.width.px(row.detail.width)`，不能把 width getter 提到不受守卫的 style 计算中。生成 computed/$derived 时只读取选中分支的值，使用框架原生依赖跟踪，不创建自己的响应式调度或缓存系统。

## 动态变量不是全部都能无损替换

对于已知单位的数值、类型清晰且可格式化的值、有限 keyword 集合，自动变量或类名选择都可行。需要保留数值范围、空值省略和多参数单位规则。

任意 raw 字符串有实际语义障碍。本轮浏览器反例：

```css
.direct {
  width: 50px;
  width: red;
}
.variable {
  width: 50px;
  width: var(--w);
  --w: red;
}
```

父容器宽 300px 时，前者是 50px，后者是 300px。第一种无效声明被忽略；第二种在 computed-value time 才失效，无法回退到前一条声明。[CSS Variables 规范](https://www.w3.org/TR/css-variables-1/#invalid-variables)

CSS-wide、undefined/null、未知或未来 CSS 语法也需要分别定义。纯编译模式可保留 raw 的静态字符串自由度；动态 raw 是接受变量语义、收窄可自动绑定范围，还是提供显式逃生路径，需要讨论。不能一边删除所有回退引擎，一边声称这些输入仍全部维持旧行为。

## 使用形态中真正需要讨论的变化

链式属性写法可以保留，模板中的直接调用也可以由框架插件隐式补齐 class 与 style。但以下边界需要明确：

1. 静态样式、有限分支仍可返回字符串类名。动态样式如果跨模块/组件只传一个字符串，字符串无法携带每个元素不同的变量值。需要可证明的调用到模板数据流，或改成能携带 class/style 的绑定对象；后者是 API 变化，不能擅自决定。
2. 普通静态函数复用、有限控制流和可分析作者 getter 可以逐步支持。动态 selector、任意方法调用、未知循环和运行时构造属性名在纯编译入口应有明确构建诊断，不悄悄带回整个样式引擎。
3. namespace/layer 等影响 CSS 产物的选项成为构建配置，不能继续任意按请求改写。现有 nonce/DOM runtime 所有权与 manifest 恢复则主要让位给构建工具 CSS 资产加载。
4. 静态 CSS 的顺序由构建和 chunk 加载决定，不再取决于运行时首次调用顺序。跨样式组合需要明确规则。
5. 非法静态样式可能改为构建期报错；动态不可达分支、debug、source map 和 HMR 的错误合同需要重新定义。
6. 全局样式和 @property 等资源不能简单全部提前加载并声称维持 useGlobalCss 的挂载/更新/释放语义。keyframes 的静态提取比较直接，资源生命周期需要单独方案。
7. 严格 CSP、SSR 的变量输出、动态覆盖和 ShadowRoot CSS 资产加载需要专门验收。本轮只测了常规 DOM，不把上轮预计算原型的 SSR/hydration 结果当作本方案的验收。

## 与现有框架的关系

[StyleX](https://stylexjs.com/docs/learn/styling-ui/using-styles/)编译样式并在运行时选择/合并，提供确定的组合规则；其简写/长属性默认规则并不等于本项目按声明顺序覆盖，不能直接照搬。可借鉴其静态编译与动态状态分离。

[Tailwind](https://tailwindcss.com/docs/detecting-classes-in-source-files)和 [UnoCSS](https://unocss.dev/guide/extracting)主要提取静态可见候选，未知动态拼接需要额外约束。它们并不替我们证明任意 TypeScript 回调的控制流等价；本项目需要 AST/符号分析和自己的作者合同。

## 推荐的主路线

优先构建「静态 CSS 产物 + 很小的框架原生绑定层」。保留用户熟悉的链式 DSL，编译器生成静态 CSS、条件类选择、变量赋值和少量校验；浏览器默认入口不包含 Builder、样式解析器、类名计算和注册缓存。数据/类型生成器继续复用。

第一阶段限定标准 Css、静态主题预设、常用单位动态值、可分析 if/switch 与有限函数复用；未知代码明确诊断。先确认动态字符串返回值与动态 raw 的合同，再迁移。若确有兼容运行时的需求，独立显式入口比默认静默回退更清晰；是否保留由产品定位决定，不是本轮已经决定的 API。

建议暂停继续优化旧运行时缓存键，把后续投入转向编译控制流、主题静态分析和 CSS 资产输出。性能证据支持这个选择，但使用范围与行为边界必须作为新架构的一部分一起确认。
